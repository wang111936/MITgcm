## 1. Source findings

The audit inspected the current `FORWARD_STEP`, `DO_THE_MODEL_IO`,
`DO_WRITE_PICKUP`, `PACKAGES_WRITE_PICKUP`, package initialization order,
`MDS_WRITEVEC_LOC/MDS_READVEC_LOC`, `pkg/flt` trajectory/pickup code, and all
P1.4 BOM owner-state routines.

It established the following source facts:

- `BOM_MAIN` returns before `DO_THE_MODEL_IO` and `DO_WRITE_PICKUP`, so both
  outputs can observe a completed P1.4 owner transaction;
- core pickup scheduling already owns suffix selection and prevents package
  pickups from becoming independent restart points;
- `MDS_WRITEVEC_LOC` supports fixed-length tiled records, writes metadata on a
  positive final record, and can represent each unsigned 32-bit ID word
  exactly in a 64-bit real record;
- a global signature file is required because changed decomposition can alter
  tiled filenames before a tiled header is readable;
- FLT initializes, advances, writes trajectories and writes pickups through
  its own COMMON blocks and prefixes; no BOM behavior requires access to them.

## 2. Closed design findings

| Finding | Risk | Frozen resolution |
|---|---|---|
| independent `bomPickupFreq` could create a package pickup without a matching ocean pickup | unrestartable checkpoint set | keep it zero; follow core checkpoint calls and suffixes only |
| recomputing output schedule on restart could duplicate or skip a frame | continuous/restart divergence | persist next/last output state in BOM pickup |
| output frequency below one ocean step can cross multiple unavailable sample times | silent missing frames | require zero or `bomOutputFreq>=deltaTClock` |
| a full 64-bit ID in `_RL` loses integers above `2^53` | identity corruption | write and read exact unsigned high/low 32-bit words |
| tiled pickup alone cannot diagnose changed decomposition before filename lookup | ambiguous missing-file failure | write and validate a global decomposition signature first |
| reading directly into COMMON state can leave a partial restart on bad input | non-transactional recovery | validate all scratch records and global IDs before one commit |
| reusing FLT files or COMMON arrays would couple two packages | coexistence changes either result | distinct prefixes, COMMON blocks, routines and static exclusion gates |

## 3. Decision

No open interface, lifecycle, precision, restart-transaction or FLT-isolation
finding remains in the design. `P1.5_INTERFACE_FREEZE.md` is suitable as the
implementation contract.

This is a design audit only. It is not runtime evidence and authorizes neither
Ready, merge, tag nor release.
