## 3. Lifecycle, schema, and scheduling audit

The source and runtime evidence establish that `BOM_MAIN` completes all
substeps and owner migration before `DO_THE_MODEL_IO` calls `BOM_OUTPUT`.
Trajectory files use only the `bom_traj` prefix, contain a 24-field header plus
one 24-field record per authoritative particle, and encode each 64-bit ID as
two exactly representable unsigned 32-bit words.

The zero-frequency case creates no trajectory file. The 150 s schedule on a
60 s model clock writes sample times 180, 300 and 480 s for scheduled times
150, 300 and 450 s, with no initial, repeated or restart frame. The next output
time is committed only after a successful frame and is restored bitwise from
pickup.

Same-layout continuous/restart comparisons retain all 24 fields and are
bitwise. Cross-layout comparisons retain the complete physical invariant view
while independently validating local `i/j`, rank and tile-owner fields against
their actual decomposition; layout metadata is not misrepresented as a
physical invariant.

## 4. Pickup transaction audit

`PACKAGES_WRITE_PICKUP` supplies the same rolling, permanent or end suffix
selected for the core MITgcm pickup. BOM has no independent checkpoint
frequency. The writer emits a global decomposition signature before tiled
state, preserving iteration, time, output frequency, next output time, global
count and capacity information.

The reader validates the signature before any tiled lookup, reads all records
into scratch state, checks schema/meta/count/time/finiteness/reserved fields,
owner layout, compact capacity and global exact-ID uniqueness, and publishes
the authoritative COMMON state only after collective success. Missing tiles,
bad schemas, duplicate IDs, corrupt time and MPI2-to-MPI4 restart all produce
the required contextual collective failure without partial publication.

Serial, MPI2 and MPI4 continuous versus 5+3 restart comparisons are bitwise for
the full authoritative state and output schedule. The production-migration
case additionally proves a WAITING particle release, a cross-rank owner change,
post-migration pickup and restart, and exact IDs above `2^53`.

## 5. FLT/BOM coexistence audit

The source contract keeps `ALLOW_FLT`/`ALLOW_BOM`, `useFLT`/`useBOM`, COMMON
state, routines and file prefixes independent. Neither package calls into or
aliases the other. All neither, FLT-only, BOM-only and combined builds and runs
pass in serial and MPI2.

Across the four runtime combinations, the core permanent pickup is byte
identical. FLT-only and combined FLT trajectory/pickup files are byte
identical. BOM-only and combined canonical trajectory/pickup records are
bitwise identical. Disabled packages create no package file.
