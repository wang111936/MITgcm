# P1.4 owner 迁移接口冻结

状态：设计冻结；实现与执行证据待本工作包完成后填写

基线：`MITGCM-BOM/phase-01-single-tile-integration@00896885a4938824bc9466eae990e23bf7329b4f`

开发分支：`MITGCM-BOM/phase-01-owner-migration`

## 1. 工作包边界

P1.4 只完成每个 nominal 粒子子步结束后的唯一 owner tile/rank 重定位，覆盖同 rank 多 tile、跨 MPI rank、周期 X 边界、多子步多 tile 路径、64 位 ID 和容量失败。P1.5 的轨迹输出、pickup/restart 和 FLT 共存验收不进入本工作包。

P1.3 已冻结的 release、age、RK2/RK4 公式、CFL、湿点插值、冻结场时间标签和逐粒子试算后提交语义继续有效。P1.4 只替换以下限制：RK 的 K2/K3/K4 与 FINAL 允许离开输入 owner，但必须仍位于输入 tile 已交换 halo 的有效插值与度量范围；K1 必须由输入 tile 拥有。每个 nominal 子步返回前必须迁移到新的唯一 owner，不能让非 owner 状态进入 `BOM_CHECK_STATE`、输出或下一子步。

## 2. 唯一 owner 规则

新增生产接口：

```text
BOM_LOCATE_OWNER(xx, yy, sourceBi, sourceBj,
                 xOwner, ownerRank, ownerBi, ownerBj, hopCount,
                 isValid, myThid)
```

- 输入坐标必须有限；Y 使用全局半开域 `[bomMapYLo,bomMapYHi)`。
- 区域 X 使用 `[bomMapXLo,bomMapXHi)`；周期 X 先由 `BOM_NORMALIZE_X` 规范到同一半开域，`xOwner` 返回规范值。
- 全局 face 表由 `BOM_INIT_MAPPING` 从 `delX/delY` 一次构造并验证严格递增；owner 查询使用二分搜索，不逐粒子线性扫描整个网格。
- 内部 face 或角点归东/北 cell，与 P1.1/P1.2 的 `[west,east) x [south,north)` 规则一致。
- 全局 cell 先映射到全局 tile，再映射到目标进程块和目标进程内 `(ownerBi,ownerBj)`。
- MPI rank 由 MITgcm 的实际全局起点表匹配，不能假定笛卡尔坐标与 communicator rank 的排列关系。
- `hopCount=max(dxTile,dyTile)`；周期 X 的 `dxTile` 使用最短环向距离。`hopCount>bomMaxHop` 为集体致命错误，不拆成未受控的隐式多轮交换。

## 3. halo-aware stage 契约

新增迁移感知 RHS/RK 接口；P1.3 公共接口及其严格 owner 行为保留：

```text
BOM_RHS_LEEWAY_HALO(...)
BOM_RK2_MIGRATE(...)
BOM_RK4_MIGRATE(...)
```

- K1 必须仍由输入 tile 拥有。
- 后续 stage 和 FINAL 可为非 owner，但 `BOM_MAP_XY2IJLOCAL` 必须给出有限局部坐标和完整四点 stencil。
- CFL 度量允许使用已交换 overlap 中的 `recip_dxF/recip_dyF`；索引不得超出 overlap。
- `bomAdvCFL<=1` 与 `OLx,OLy>=2` 是本工作包的 stage 支持前提；启动门禁明确检查。
- 任一 stage 超出 halo、湿权重不足、非有限或 CFL 超限时，仍按 P1.3 首失败顺序回滚该粒子子步。
- FINAL 的源 tile 诊断只是试算结果；迁移成功后必须在目标 owner 上以 `dtGuard=0` 重新映射和刷新诊断。

## 4. 迁移事务

新增生产接口：

```text
BOM_PARTICLE_EXCHANGE(exchangeTime, exchangeIter, exchangeSubstep,
                      myThid)
```

调用顺序固定为：

1. 对本 rank 全部紧凑 owner 槽定位目标并计算 hop；
2. 统计本地 tile 移动与跨 rank 发送，不改权威 owner 数组；
3. 交换逐 rank 粒子计数，检查发送/接收缓冲上限；
4. 交换整数 metadata 和最小实数状态；
5. 合并本地保留、同 rank 迁移与远端接收记录，预检每个目标 tile 的最终需要量；
6. 精确恢复 ID，检查 metadata、状态和目标 owner；
7. 每个目标 tile 按完整 `INTEGER*8` ID 升序排序；
8. 在目标 tile 重新计算 `bomI/bomJ` 及 ocean/wind/drift 诊断；
9. 全局确认全部试算有效后，一次性替换 `bomNPartTile` 与所有 SoA 槽；
10. 清零紧凑尾槽，随后才允许 `BOM_CHECK_STATE`。

若全局没有粒子改变 tile/rank、也没有周期规范化，例程直接返回，不重写槽，保证 P1.3 非迁移路径逐位不变。

## 5. MPI ABI 与 64 位 ID

只传输真正跨 rank 的记录。每个粒子固定使用：

- 5 个 `MPI_INTEGER`：ID 高 32 位、ID 低 32 位、status、目标 `bi`、目标 `bj`；
- 4 个 `_MPI_TYPE_RL`：规范化 `x`、`y`、release time、age。

ID 低字采用 schema 1 的有符号 32 位表示，接收端以整数算术恢复正 `INTEGER*8`。禁止把 ID 放入 `_RL`，也不依赖非标准 `MPI_INTEGER8`。发送按目标 rank 分组，使用 `MPI_Alltoall` 交换计数，再以两个 `MPI_Alltoallv` 交换整数和实数包。

## 6. 容量与失败语义

- `bomMaxExchange` 是每 rank 单次跨 rank 发送或接收记录上限；生产默认不得小于本工作包支持的全局初值上限。
- 发送/接收超限必须输出 `rank`、`direction=SEND|RECV`、`needed`、`limit`，然后集体停止；不得截断。
- 目标 tile 超限必须输出 `rank`、目标 tile、`needed`、`limit`。
- 非法 owner、hop、metadata、ID 恢复或目标刷新必须带 exchange time/iter/substep 和原 ID 上下文。
- 任一 rank 失败时，所有 rank 在同一 collective 边界停止；不得有部分 rank 提交迁移。

## 7. 确定性

- 每次发生迁移后，所有本地目标 tile 都按完整 64 位 ID 排序，因此到达顺序和 MPI 分组不影响权威槽序。
- 目标 owner 刷新使用与普通 P1.3 FINAL 相同的严格 `BOM_RHS_LEEWAY(...,dtGuard=0)`。
- 相同输入和编译器下，按 ID 排序的 1/2/4 ranks 状态目标为 bitwise 一致；任何例外必须在修改判据前形成单独设计决定和逐字段上界。
