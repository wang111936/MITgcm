## 1. 工作包边界

P1.5 完成 Phase 1 的最后三项能力：迁移后权威粒子轨迹输出、相同分解
的 pickup/restart，以及现有 MITgcm `pkg/flt` 与 `pkg/bom` 的独立共存。
P1.1—P1.4 已冻结的状态、映射、环境场、Leeway、RK2/RK4、release、
事务提交、唯一 owner、MPI 交换和失败语义必须保持。

本工作包不增加 Stokes、惯性、弹簧、生物、搁浅、随机过程、EXCH2、
旋转/曲线网格、OpenMP 粒子推进或改变分解的 restart。P1.5 不修改
FLT 的状态、文件格式、数值算法或运行参数。

## 2. 生命周期挂接与时间语义

新增生产接口：

```text
BOM_INIT_OUTPUT_SCHEDULE(startTime, myThid)
BOM_OUTPUT(myTime, myIter, myThid)
BOM_WRITE_TRAJECTORY(sampleTime, scheduledTime, myIter, myThid)
BOM_WRITE_PICKUP(suffix, myTime, myIter, myThid)
BOM_READ_PICKUP(myThid)
```

- `BOM_MAIN` 仍在 `FORWARD_STEP` 中先完成全部子步、迁移和 step-end
  `BOM_CHECK_STATE`；它不直接写文件。
- `DO_THE_MODEL_IO` 随后独立调用 `BOM_OUTPUT`。因此任何输出记录都已
  位于唯一 owner，不能包含候选或非 owner 状态。
- `PACKAGES_WRITE_PICKUP` 在 MITgcm 核心选定 rolling/permanent/end
  checkpoint 后，以同一个 suffix 调用 `BOM_WRITE_PICKUP`。
- `BOM_INIT_VARIA` 先清零状态；`nIter0==bomInitialIter` 时读取 schema 1
  初值并初始化输出调度，`nIter0>bomInitialIter` 时读取同 suffix 的 BOM
  pickup，`nIter0<bomInitialIter` 明确失败。
- `bomInitialIter` 新增到 `BOM_PARM01`，默认 `0`，语义与 FLT 的
  `FLT_Iter0` 类似，但两者变量和文件完全独立。

`bomPickupFreq` 在 Phase 1 继续要求为零。BOM pickup 只跟随核心
`chkPtFreq`、`pChkPtFreq` 和 `writePickupAtEnd`，不能生成没有对应海洋
pickup 的孤立 BOM 重启点。

## 3. 轨迹调度

新增持久状态：

```text
_RL     bomNextOutputTime
LOGICAL bomOutputScheduleReady
```

- `bomOutputFreq=0` 完全关闭轨迹输出，不创建 `bom_traj*` 文件；
- 正频率必须有限且不小于 `deltaTClock`，否则启动失败，避免一个海洋步
  跨过多个无法采样的输出时刻；
- 初始运行设置 `bomNextOutputTime=startTime+bomOutputFreq`，初始化 I/O
  调用不写初始状态；
- 每个 step-end 若 `myTime` 首次到达/越过 `bomNextOutputTime`，只写
  一次当前 step-end 权威状态；记录同时包含 scheduled time 与实际
  sample time；成功后把 next time 精确增加一个频率；
- `bomOutputFreq>=deltaTClock` 保证一次调用最多越过一个计划时刻；若
  调度状态损坏或出现多重越过，带 next/current/frequency 上下文停止；
- 非整除频率采用“第一个到达或越过计划时刻的 step-end”规则。例如
  `deltaTClock=60 s`、`bomOutputFreq=150 s` 从零开始时，样本时间固定为
  `180,300,480,... s`，无漏写和重复；
- next time 在 pickup 中逐位保存；一帧成功后 next 已严格大于当前时间，
  因而 restart 初始化或同一步重复调用不会重写最近一帧。

## 4. 轨迹文件契约

每次输出事件创建新的 tiled MDS 文件，固定前缀：

```text
bom_traj.<10-character MITgcm suffix>.<iG>.<jG>.data
bom_traj.<10-character MITgcm suffix>.<iG>.<jG>.meta
```

suffix 使用 `rwSuffixType` 与 `RW_GET_SUFFIX`；默认类型使用十位
`myIter`。文件精度固定 `precFloat64`，每个 tile 第一条为 24-field
header，后续每个权威粒子一条 24-field record。最后一条写调用必须
生成记录数正确的 MDS meta；零粒子 tile 仍写一个 header 和 meta。

Header 字段按顺序固定为：

1. schema=`1`；2. fields=`24`；3. tile count；4. global expected count；
5. coordinate code=`1`；6. ID encoding=`1`；7. precision bits=`64`；
8. iteration；9. sample time；10. scheduled time；11. 本帧成功后的 next output time；
12. `nPx`；13. `nPy`；14. global tile-I origin；15. global tile-J origin；
16. owner rank；17. local `bi`；18. local `bj`；19—24. reserved zero。

Particle record 字段按顺序固定为：

1. unsigned ID high word；2. unsigned ID low word；3. status；
4. sample time；5. iteration；6—7. native `x/y`；8. release time；
9. age；10—11. local `i/j`；12—13. ocean east/north `[m s-1]`；
14—15. 10 m wind east/north `[m s-1]`；16—17. drift east/north
`[m s-1]`；18. owner rank；19—20. local owner `bi/bj`；
21. coordinate code=`1`；22—24. reserved zero。

ID 不以完整整数写入 `_RL`。两个无符号 32 位 word 各自可由 IEEE-64
精确表示，读取器按 schema 1 恢复正 `INTEGER*8`。每 tile 权威槽已经
按完整 ID 排序；验收读取器合并所有 tile 后再次按完整 ID 重组，并要求
每个 `(sampleTime,id)` 恰有一条。

同一分解的连续与 restart 比较保留完整 24-field record，必须逐位一致。
跨分解比较不能把布局字段伪装成物理不变量：轨迹 record 的 1—9、
12—17、21—24 字段逐位比较；local `i/j`、rank、local `bi/bj` 按各自
分解逐项验证。该口径不删除输出字段，也不放宽同分解 restart 判据。

## 5. Pickup 文件契约

每个核心 checkpoint 同时写：

```text
pickup_bom.<suffix>.sig.data/.meta
pickup_bom.<suffix>.<iG>.<jG>.data/.meta
```

全局 `.sig` 是 16-field 单记录 MDS 文件，由 rank 0 写入：schema、字段
数、`nPx/nPy`、`sNx/sNy`、`nSx/nSy`、`Nx/Ny`、`bomMaxPartTile`、
全局 expected count、iteration、time、`bomOutputFreq` 和
`bomNextOutputTime`。读取任何 tiled state 前必须先验证 `.sig`。

每个 tiled pickup 使用与轨迹相同的 24-field record 长度。Header 固定
为 schema、字段数、tile count、global expected count、coordinate/ID/
precision、iteration、time、next output time、output frequency、
`nPx/nPy/sNx/sNy/nSx/nSy`、global tile origins、rank、bi、bj、
`bomMaxPartTile`。Particle record 保存 ID 高低字、status、`x/y`、
release、age、`i/j`、六个 ocean/wind/drift 诊断、rank、bi、bj 和
reserved zero。

P1.5 只支持完全相同的 `nPx/nPy/sNx/sNy/nSx/nSy/Nx/Ny` 和 tile origins。
改变分解时，全局 `.sig` 必须在尝试打开新分解的 tiled 文件前输出 stored
与 current signature 并集体停止。

## 6. Pickup 恢复事务

恢复顺序固定为：

1. 解析核心 pickup suffix；读取并验证全局 `.sig`、时间、迭代、输出
   频率、全局计数、编译容量和分解签名；
2. 用 `ioUnit=-2` 预检每个期望 tiled 文件；缺失文件先转成 BOM 上下文
   错误，再在 collective 边界停止；
3. 把所有 header/particle records 读入非权威 scratch arrays；
4. 验证 schema/meta/物理记录数、有限值、reserved 字段、status、
   release/age、精确 ID、tile owner、局部索引和紧凑容量；
5. 用两个整数 word 做全局 exact ID 预算、唯一性和 expected-count 检查；
6. 全局确认全部 scratch 状态有效后，一次性发布 owner arrays、
  `bomNPartExpected` 和 next-output 调度状态，并清零紧凑尾槽；
7. 第一个 `BOM_MAIN` 在刷新场后仍执行正常 `BOM_CHECK_STATE`，作为
   restart 后的独立运行时复核。

任何 schema、文件、签名、时间、计数、ID、状态或 owner 错误都不能
部分提交权威状态。相同分解连续运行与 restart 运行的所有权威字段和
`bomNextOutputTime` 必须 bitwise 一致。

跨分解只比较 pickup 的物理规范化视图：signature 的 schema/fields、
`Nx/Ny`、容量、count、iteration/time/frequency/next time，以及 particle
record 的 ID/status/`x/y`/release/age、ocean/wind/drift 和 reserved 字段。
分解签名、local `i/j` 与 owner rank/tile 必须匹配各自布局，不能跨布局
要求相同数值。

## 7. FLT 共存边界

- `PACKAGES_CONFIG.h` 中 `ALLOW_FLT` 与 `ALLOW_BOM` 独立；`useFLT` 与
  `useBOM` 独立；四种编译/运行组合均须成立。
- `FORWARD_STEP` 保持 FLT 后 BOM 的并列调用；两者不相互调用。
- BOM 生产文件禁止 include `FLT.h/FLT_SIZE.h/FLT_BUFF.h`，禁止引用
  `npart_tile`、`npart`、`ipart` 等 FLT COMMON 状态。
- FLT 文件保持 `float_trajectories*`、`float_profiles*` 和
  `pickup_flt*`；BOM 只使用 `bom_traj*` 与 `pickup_bom*`。
- `PACKAGES_WRITE_PICKUP` 可顺序调用 FLT 与 BOM writer，但 suffix
  共享不等于状态或格式共享。
- 共存验收必须证明：加入 BOM 不改变 FLT trajectory/pickup 的字节；
  加入 FLT 不改变 BOM 按 ID canonical trajectory、pickup 或最终状态。

## 8. 失败、线程和 I/O 约束

- 非零 Phase-1 BOM 状态继续要求 `nTx*nTy=1`；I/O 只由 master thread
  执行并在返回前 barrier。
- 输出前调用完整状态预算；pickup writer 不修复、不重排、不刷新状态。
- 文件打开/记录错误必须包含 prefix、suffix、rank/tile、record、iter/time；
  不能仅依赖 Fortran `STOP` 返回码判定失败。
- 输出或 pickup 不允许调用生产测试 hook，也不写入仓库目录。
- 所有构建、运行、二进制和原始日志使用仓库外唯一目录；历史 P1.4
  和前序证据不得覆盖。
