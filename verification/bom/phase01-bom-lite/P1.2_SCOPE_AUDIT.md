## Finding P1.2-A — production diagnostic path is not connected

Severity: **BLOCKER**

The frozen lifecycle requires nonzero-particle `BOM_MAIN` to build the P1.2
fields and validate existing particle positions through mapping and wet-pair
interpolation without changing position, ID, status, release time, age, or
owner counts.  It also requires the caller of `BOM_INTERP_WET_PAIR` to stop
with tile, local indices, and wet weight when interpolation is invalid.

The reviewed `BOM_MAIN` only calls `BOM_BUILD_FIELDS`.  No production routine
calls `BOM_MAP_XY2IJLOCAL` and `BOM_INTERP_WET_PAIR` for the current owner
records, and no production caller implements the contextual P1-N05 stop.  The
9/9 interpolation gate invokes `BOM_INTERP_WET_PAIR` directly from a
verification routine and therefore cannot prove the frozen lifecycle or
caller-side failure contract.

Required correction before P1.2 can pass:

1. after field publication, perform a non-moving diagnostic pass over the
   current owner records;
2. map each committed `bomX/bomY` on its current tile, require the frozen owner
   and stencil conditions, and interpolate the authoritative east/north pair;
3. publish only diagnostic `bomI/bomJ/bomVEast/bomVNorth` values after a valid
   result;
4. on failure, print particle/tile context, local indices, and wet weight, then
   terminate collectively;
5. add serial and MPI4 positive lifecycle tests proving bitwise preservation of
   authoritative particle state, plus caller-level P1-N05 negative tests.

This correction must not add RHS evaluation, RK stages, position updates,
release transitions, owner migration, wind, or Stokes.

## Finding P1.2-B — finite-geometry rejection is incomplete

Severity: **REQUIRED ROBUSTNESS FIX**

`BOM_INIT_MAPPING` checks each individual `delX/delY` value, but does not check
whether their accumulated spans, derived high bounds, scale, or tolerance
remain finite.  Its monotonicity condition checks the current face value for
NaN but does not explicitly check both endpoints, so a non-finite terminal
stored face can escape initialization.  `BOM_NORMALIZE_X` also lacks a
post-arithmetic finite check when reducing an arbitrary finite periodic input.

The frozen contract requires non-finite geometry to stop without publishing
partial mapping state and says any finite equivalent longitude is normalized.
The current P1-N04 matrix covers non-positive spacing and inconsistent bounds,
but not non-finite origin/spacing/faces, accumulated overflow, or extreme
finite periodic input.

Required correction before P1.2 can pass:

1. validate accumulated spans and every derived mapping scalar before use;
2. explicitly validate both endpoints of every inspected stored face interval;
3. ensure normalization returns an explicit invalid result if periodic
   arithmetic cannot remain finite;
4. add focused negative probes for non-finite/overflowing geometry and a
   finite-extreme normalization probe.
