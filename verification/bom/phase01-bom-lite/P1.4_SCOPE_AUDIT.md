## 1. Audit method

The audit derived its checklist from `P1.4_INTERFACE_FREEZE.md`, inspected the
production owner locator, halo RK wrappers, exchange transaction and caller,
required direct serial/MPI2/MPI4 runtime evidence for each named acceptance
case, and verified both the P1.4 and predecessor SHA-256 manifests.  A clean
exact source head is recorded independently of the build and run trees.

Source searches are used only for structural invariants.  Runtime behavior,
bitwise state comparisons and expected collective fatal diagnostics decide the
functional and failure-transaction requirements.

## 3. Source and transaction audit

The final source inspection confirms:

- the global face table is built once and owner lookup is binary rather than a
  per-particle scan across the full grid;
- periodic X normalization and face snapping preserve a single half-open
  owner, while regional X and global Y are not silently clamped;
- rank ownership is derived from MITgcm rank origins rather than assumed MPI
  Cartesian rank order;
- K1 remains on the source owner and K2/K3/K4/FINAL use only validated
  exchanged overlap; final target diagnostics are refreshed on the new owner;
- cross-rank packets contain five `MPI_INTEGER` and four `_MPI_TYPE_RL`
  values, keeping both ID words out of floating-point storage;
- count exchange precedes both Alltoallv operations; SEND, RECV and final tile
  capacities are checked before authoritative arrays are replaced;
- all target tiles are reconstructed and sorted by full `INTEGER*8` ID before
  one collective commit; a collective error leaves the original owner arrays
  intact;
- the no-movement path returns without rewriting authoritative slots.

## 4. Named acceptance and decomposition audit

P1-X01 covers same-rank horizontal, vertical and corner transitions. P1-X02
adds MPI-rank and periodic-X transitions. P1-X03 executes 16 nominal substeps
with a legal direct hop after every substep. P1-X04 migrates IDs greater than
`2^53`.  Six independent state comparisons show bitwise equality across the
supported decompositions.

P1-N03b separately proves collective SEND, RECV and destination-tile capacity
failure without truncation.  The hop gate records ID, source, target,
`hop/limit`, iteration, substep and time.  The halo-stencil gate attributes the
first failure to K2/STENCIL and preserves the original coordinates exactly.
