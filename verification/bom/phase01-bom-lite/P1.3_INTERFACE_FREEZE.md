## 1. 参考审计结论

### 1.1 MITgcm 生命周期

`forward_step.F` 在本海洋步动力和字段交换完成后把时间计数更新为步末值，再依次调用 `FLT_MAIN` 与 `BOM_MAIN`。因此 P1.3 固定以下时间语义：

```text
t0 = myTime - deltaTClock
t1 = myTime
BOM_MAIN: [t0,t1] -> t1
```

`LOAD_FIELDS_DRIVER` 在时间计数更新前以 `(t0,myIter-1)` 调用 `EXF_GETFORCING`，随后海洋动力推进并把计数更新到 `(t1,myIter)`，最后才调用 BOM。因此 `BOM_BUILD_FIELDS(myTime,myIter,myThid)` 同时快照两种时间标签不同的字段：步末 `uVel/vVel@t1`，以及本海洋步请求并使用的 EXF `uwind/vwind@t0`。P1.3 在整个粒子区间内冻结这组混合时间层，不读取 old/new 场，不按 RK stage time 对环境场做时间插值，也不声称真实时变环境场具有二阶或四阶时间精度。

### 1.2 锁定 Julia `Leeway!`

锁定 checkout 处于 detached HEAD `156557359185e4413ce82829f3ed26a4eb8c6283`。其 `src/physics.jl` 明确定义：

```text
u_leeway = u_water + alpha * u_wind
v_leeway = v_water + alpha * v_wind
```

输入的 m/s 速度由 Julia 数据层转换为 km/day，换算为 `1 m/s = 86.4 km/day`；位置和时间分别采用 equirectangular km 与 day。MITGCM-BOM 保持 m、s、m/s 与原生 MITgcm 坐标，在对照前做显式单位转换。

Julia 参考只裁决上述 Leeway 代数组合。它默认使用自适应 `Tsit5` 求解器，不裁决 P1.3 的固定步 RK2/RK4、release-time、MITgcm C-grid、湿点 stencil、tile owner、CFL 或异常策略。Julia `Leeway!` 不含 Stokes。

### 1.3 MITgcm FLT

FLT 提供了时间步调用、局部插值和 RK 实现参考，但 P1.3 不复用 `FLT_*` 例程或 COMMON：

- `bomIntegrator='RK2'` 是显式中点法，不采用 FLT 历史变体的隐含状态语义；
- `bomIntegrator='RK4'` 是经典四级格式；
- P1.3 使用 P1.2 的原生坐标映射、east/north 湿点 pair 插值和显式有效性返回；
- 所有 ID、状态、诊断、参数和未来迁移接口保持 BOM 独立命名。

### 1.4 EXF 风

`EXF_FIELDS.h` 定义 `uwind/vwind` 为格心处 10 m zonal/meridional 风速，单位 m/s，正方向分别为东和北。`EXF_GETFFIELDS` 仅在 `useAtmWind=.TRUE.` 时更新这两个风分量。

P1.3 因此要求 `bomWindSource='EXF'` 同时满足：

1. 编译时有 `ALLOW_EXF`；
2. 运行时 `useEXF=.TRUE.`；
3. 运行时 `useAtmWind=.TRUE.`。

`ALLOW_ATM_WIND` 只决定 EXF 的默认 `useAtmWind`，最终以运行时值为准。BOM 只复制 EXF 已完成空间/时间处理、并在 `LOAD_FIELDS_DRIVER(t0,myIter-1)` 请求的当前 `uwind/vwind`，不直接读取 EXF 文件，不重做 EXF 时间插值，也不使用 wind stress 替代 10 m 风速。

## 2. 工作包边界

P1.3 包含：

1. 海洋步内确定性的等长粒子子步；
2. WAITING 到 ALIVE 的精确 release-time 分割；
3. 海流与可选 EXF 10 m 风组成的 Leeway RHS；
4. Cartesian 与未旋转 spherical-polar 的 SI/原生坐标率转换；
5. 显式中点 RK2 与经典 RK4；
6. 每个 RK stage 的映射、湿点、有限数、CFL 和当前 owner 检查；
7. 每粒子每子步的试算后提交和诊断刷新；
8. 单 tile 正向、解析、收敛、依赖负测和前序回归。

P1.3 不包含：

- tile/rank owner 迁移、交换缓冲、重复 hop 或开放边界 `BOM_OUTSIDE` 转换；
- Stokes、old/new 环境场、stage-time 场插值或真实时变场高阶精度；
- BOM/EBOM/EBOMB 惯性、弹簧、生物、搁浅或随机过程；
- 轨迹文件、pickup 或完整 FLT/BOM 共存验收；
- EXCH2、旋转/曲线网格、LLC、cubed-sphere 或 OpenMP 生产支持；
- 修改 FLT 源码、状态或文件格式。

任一 stage 或最终候选位置离开当前 owner tile 时，P1.3 必须带上下文终止，不能借用 halo 静默完成跨 tile 运动。P1.4 才把该拒绝边界替换为受测试的 owner 迁移。

## 3. 冻结环境场

### 3.1 数据布局

P1.3 保留 P1.2 海流数组，并新增两个 BOM 自有风场快照：

```text
bomGridUWork, bomGridVWork
bomGridVEast, bomGridVNorth
bomGridWindEast, bomGridWindNorth
```

风场数组使用与海流 pair 相同的单层形状：

```text
(1-OLx:sNx+OLx, 1-OLy:sNy+OLy, 1, nSx, nSy)
```

它们属于 BOM COMMON，不与 EXF 数组别名。`bomFieldsReady` 只有在所选海流和风场全部复制、mask、标量 halo exchange、有限性检查完成后才能为真。

P1.3 新增独立风场时间标签：

```text
bomFieldTime, bomFieldIter          = t1, myIter
bomWindFieldTime, bomWindFieldIter  = t0, myIter-1
```

`bomFieldTime/bomFieldIter` 继续只描述 P1.2 步末海流快照；不能把它们复用成 EXF 风的伪步末标签。`bomWindSource='NONE'` 时风数组为零，但仍写入本海洋步的 `t0/myIter-1`，使诊断元数据确定。

P1.3 还新增全局权威计数 `bomNPartExpected`：`BOM_INIT_STATE` 将其重置为 0，`BOM_READ_INITIAL` 只有在输入、唯一 owner 和全局分配全部成功后才将其发布为 `nInput`。它不是容量上限；`bomMaxParticles` 仍只是上限。P1.3 不创建、删除或迁移粒子，因此每次完整状态预算都要求当前全局 owner 数精确等于 `bomNPartExpected`。

### 3.2 `BOM_BUILD_FIELDS` 扩展契约

```text
BOM_BUILD_FIELDS(myTime, myIter, myThid)
```

执行顺序固定为：

1. 先令 `bomFieldsReady=.FALSE.`；
2. 按 P1.2 契约构造 `bomGridVEast/bomGridVNorth`；
3. `bomWindSource='NONE'` 时把两个 BOM 风场数组确定性置零；
4. `bomWindSource='EXF'` 时把格心 east/north `uwind/vwind` 复制到 BOM 单层数组，干点置零；
5. 对两个 BOM 风分量分别做标量 halo exchange；
6. 检查所有湿点所选字段有限、所有干点为零；
7. 发布海流标签 `bomFieldTime=myTime`、`bomFieldIter=myIter`；
8. 发布风标签 `bomWindFieldTime=myTime-deltaTClock`、`bomWindFieldIter=myIter-1`；
9. 最后设置 `bomFieldsReady=.TRUE.`。

本例程不修改 `uVel/vVel`、EXF `uwind/vwind`、mask 或 forcing 状态。任何部分失败都不能留下可读的旧/半新混合快照。

## 4. Leeway RHS 与坐标率

### 4.1 冻结公式

对每个有效 stage 位置，先用 P1.2 相同映射和湿点权重分别采样海流与所选风场：

$$
V_E = U_E + c_W W_E,\qquad V_N = U_N + c_W W_N,
$$

其中 $c_W=$ `bomLeewayWindCoeff`。`bomWindSource='NONE'` 时 $W_E=W_N=0$ 且要求 $c_W=0$。Phase 1 不使用 $(1-c_W)U$，也不加入 Stokes。

Cartesian 原生坐标必须为米：

$$
\dot x=V_E,\qquad \dot y=V_N.
$$

spherical-polar 原生坐标为 degree：

$$
\dot\lambda=\frac{180}{\pi}\frac{V_E}{r_\mathrm{Sphere}\cos\phi},\qquad
\dot\phi=\frac{180}{\pi}\frac{V_N}{r_\mathrm{Sphere}}.
$$

实现使用 MITgcm 的 `rSphere`，并在除法前要求 `rSphere` 有限且为正、纬度有限，并要求

```text
abs(cos(phi)) >= sqrt(EPSILON(oneRL))
```

否则返回 `BOM_FAIL_NONFINITE`。这里使用当前代码库已经采用的 `EPSILON(oneRL)` 写法，不使用类型宏作为 intrinsic 实参。P1.2 已拒绝包含极点的配置；P1.3 仍在每个 stage 重查候选纬度。

### 4.2 `BOM_RHS_LEEWAY`

冻结逻辑接口为：

```text
BOM_RHS_LEEWAY(
  xx, yy, dtGuard, bi, bj,
  rhsX, rhsY, ix, jy,
  oceanEast, oceanNorth,
  windEast, windNorth,
  driftEast, driftNorth,
  wetWeight, stageCFL,
  isOwner, isValid, failCode,
  myThid)
```

例程必须：

- 要求 `dtGuard` 有限且非负；
- 映射 stage 位置并要求 stencil 完整；
- 对海流和可选风场执行共同 mask 语义的 pair 插值；
- 计算 Leeway east/north 速度和原生坐标率；
- 用数学 floor 固定最近 C 点及半格 tie-break：
  `iC=floor(ix+0.5)`、`jC=floor(jy+0.5)`，精确半格归东/北侧 C 点；要求 `iC=1:sNx`、`jC=1:sNy` 且对应 `recip_dxF/recip_dyF` 有限并为正；
- 用该 C 点的 `recip_dxF/recip_dyF` 计算
  `max(abs(dtGuard*driftEast*recip_dxF), abs(dtGuard*driftNorth*recip_dyF))`；
- 要求 `stageCFL <= bomAdvCFL`；
- 返回当前 tile 的 `isOwner`，由 P1.3 调用层要求为真；
- 对失败返回 `isValid=.FALSE.`、稳定 `failCode` 和可诊断的局部量，不自行提交粒子状态。

`dtGuard` 始终是当前有效子步的完整时长，即使该 RHS 是 RK 半步 stage。这样 CFL 约束不会因 stage 系数为 1/2 而被静默放宽。最终位置诊断刷新使用 `dtGuard=0`，它只验证位置/字段，不重复约束已验收子步。

稳定失败类别至少包括：`BOM_FAIL_MAP`、`BOM_FAIL_STENCIL`、`BOM_FAIL_INTERP`、`BOM_FAIL_NONFINITE`、`BOM_FAIL_CFL`、`BOM_FAIL_OWNER`、`BOM_FAIL_STATE` 和 `BOM_FAIL_RELEASE`。同一次调用只发布首个失败，优先级固定为：调用层状态/release 检查；RHS 输入及 `dtGuard` 非有限；全局/本 tile 映射失败；离开当前 owner；缺失 stencil；湿点插值失败；派生速度、坐标率或网格度量非有限/非正；CFL 超限。

P1.3 RHS 实现增量固定以下数值编码，后续不得复用或改变语义：

| 失败类别 | 数值 | 含义 |
|---|---:|---|
| `BOM_FAIL_NONE` | 0 | 无失败 |
| `BOM_FAIL_MAP` | 1 | 全局或本 tile 映射失败 |
| `BOM_FAIL_OWNER` | 2 | stage 位置离开当前 owner |
| `BOM_FAIL_STENCIL` | 3 | 缺失四点插值 stencil |
| `BOM_FAIL_INTERP` | 4 | 湿点或场插值失败 |
| `BOM_FAIL_NONFINITE` | 5 | 非有限或非正派生量/度量 |
| `BOM_FAIL_CFL` | 6 | stage CFL 超限或其乘法不可表示 |
| `BOM_FAIL_STATE` | 7 | 调用层状态非法 |
| `BOM_FAIL_RELEASE` | 8 | 调用层 release 时间非法 |

`failStage` 同时固定为 `NONE=0`、`K1=1`、`K2=2`、`K3=3`、`K4=4`、`FINAL=5`；`FINAL` 是已验收候选位置的诊断刷新，不是新的 RK stage。

## 5. 固定子步与 release-time

### 5.1 子步划分

在任何 `CEILING` 或整数转换前，`BOM_CHECK` 必须要求 `deltaTClock`、`bomDeltaTTarget` 和 `bomAdvCFL` 有限且为正，`bomLeewayWindCoeff` 有限且满足既有范围。运行时还必须要求 `myTime` 与 `t0=myTime-deltaTClock` 有限。随后固定：

```text
subRatio = deltaTClock / bomDeltaTTarget
require finite(subRatio) and 0 < subRatio <= DFLOAT(HUGE(nSub))
nSub = max(1, CEILING(subRatio))
dtSub = deltaTClock / nSub
tSub0 = myTime - deltaTClock + isub*dtSub
tSub1 = tSub0 + dtSub
```

`nSub`、`dtSub` 和每个端点还必须分别通过正值/有限性检查；整数不可表示、除法下溢为零或端点溢出都在推进前明确失败。`isub=0:nSub-1`，最后一个端点强制使用 `myTime`，避免累计舍入使区间缺口或重叠。不得采用若干完整目标步加一个短尾步。

### 5.2 状态转换

对每个 nominal 子步 `[tSub0,tSub1]`：

| 输入状态/时间 | 行为 | 有效积分时长 |
|---|---|---:|
| `BOM_WAITING` 且 `releaseTime > tSub1` | 保持 WAITING，位置/age 不变 | 0 |
| `BOM_WAITING` 且 `releaseTime <= tSub0` | 在 `tSub0` 转 ALIVE | `dtSub` |
| `BOM_WAITING` 且 `tSub0 < releaseTime < tSub1` | 精确从 release time 积分到子步末 | `tSub1-releaseTime` |
| `BOM_WAITING` 且 `releaseTime == tSub1` | 子步末转 ALIVE，位置/age 不变 | 0 |
| `BOM_ALIVE` | 完整积分 | `dtSub` |

release time 与端点比较固定使用

```text
timeTol = 16*EPSILON(oneRL)*max(oneRL,abs(tSub0),abs(tSub1),abs(releaseTime))
```

当且仅当 `abs(releaseTime-endpoint) <= timeTol` 时把它归到该端点；不能把真正位于区间内部的 release 吸附到端点。所有时间输入及 `timeTol` 必须有限。试算 `ageCandidate=bomAge+dtActive` 前要求 `bomAge` 有限且非负、`dtActive` 有限且非负，并用 `bomAge <= HUGE(bomAge)-dtActive` 防止加法溢出。`bomAge` 只在位置和全部候选状态成功提交后增加有效积分时长。

release 位于 `tSub1` 时虽然有效积分时长为 0，仍必须在当前位置执行 `FINAL` 映射/场诊断刷新，成功后把状态、位置和最终诊断作为一次事务提交。P1.3 的有效紧凑 owner 槽只允许 `BOM_ALIVE` 与 `BOM_WAITING`；`BOM_UNUSED`、`BOM_OUTSIDE`、`BOM_DEAD_BIO`、`BOM_BEACHED`、`BOM_INVALID` 或其他值一律返回 `BOM_FAIL_STATE`。P1.3 不产生 OUTSIDE、DEAD_BIO 或 BEACHED。

## 6. RK2/RK4 与事务提交

### 6.1 冻结格式

显式中点 RK2：

```text
k1 = f(qn)
k2 = f(qn + 0.5*dt*k1)
q1 = qn + dt*k2
```

经典 RK4：

```text
k1 = f(qn)
k2 = f(qn + 0.5*dt*k1)
k3 = f(qn + 0.5*dt*k2)
k4 = f(qn + dt*k3)
q1 = qn + dt*(k1 + 2*k2 + 2*k3 + k4)/6
```

每个 `f` 都是完整 `BOM_RHS_LEEWAY` 调用。每个 stage 位置和最终 `q1` 必须有限、可映射、有湿点 stencil，且仍由输入 `(bi,bj)` owner。最终候选位置还要用 `dtGuard=0` 刷新映射和诊断；该刷新不是额外 RK stage。

### 6.2 冻结接口

```text
BOM_RK2(x0, y0, dt, bi, bj,
        x1, y1, ix, jy,
        oceanEast, oceanNorth,
        windEast, windNorth,
        driftEast, driftNorth,
        wetWeight, stageCFL,
        failStage, failCode, isValid, myThid)

BOM_RK4(x0, y0, dt, bi, bj,
        x1, y1, ix, jy,
        oceanEast, oceanNorth,
        windEast, windNorth,
        driftEast, driftNorth,
        wetWeight, stageCFL,
        failStage, failCode, isValid, myThid)
```

两个例程都是每粒子试算内核：不得写 `bomX/bomY/bomStatus/bomAge`、owner 计数或其他粒子槽。调用层同样先在局部量中形成 `statusCandidate/ageCandidate`；只有位置、状态、age、所有 stage 与最终刷新全部有效后，才一次性提交该粒子当前子步的：

```text
bomX, bomY, bomStatus, bomAge, bomI, bomJ,
bomVEast, bomVNorth,
bomWindEast, bomWindNorth,
bomDriftEast, bomDriftNorth
```

RK2 与 RK4 的展开参数及诊断顺序都是 P1.3 的精确 ABI。成功时这些诊断来自最终候选位置的 `dtGuard=0` RHS 刷新，因此 `stageCFL=0`；失败时诊断保留首次失败 RHS，或在候选坐标算术失败时保留最近一次成功 stage 的上下文。

任何失败都返回 `x1=x0`、`y1=y0` 和 `isValid=.FALSE.`。输入位置或步长非法且尚未进入 stage 时使用 `failStage=NONE`；对应 stage 坐标形成或 RHS 失败分别使用 `K1`、`K2`、`K3` 或 `K4`；加权最终坐标形成或最终刷新失败使用 `FINAL`。成功时 `failStage=NONE`、`failCode=BOM_FAIL_NONE`。

最终诊断定义为“最终已验收位置处的冻结场样本”，不是 RK 加权平均，也不是最后一个 stage 的缓存。零 RHS 时必须保持位置 bitwise 不变。

### 6.3 `BOM_MAIN`

P1.3 的 `BOM_MAIN` 顺序固定为：

1. 零粒子立即返回；
2. 构造一个完整冻结环境快照；
3. 验证海流标签为 `(myTime,myIter)`、风标签为 `(myTime-deltaTClock,myIter-1)` 且 ready；
4. 计算等长 `nSub/dtSub`；
5. 逐子步、逐本线程 owner tile、逐紧凑槽处理状态和 release；
6. 对有效积分区间调用所选 RK 内核，成功后提交；
7. 按 `bomCheckEverySubstep` 执行完整 owner/ID/状态预算；
8. 无论该开关为何值，都执行每 stage 的映射、湿点、有限数、CFL、owner 硬检查，并在海洋步末执行完整预算；
9. 聚合错误后输出时间、迭代、子步、stage、rank、tile、slot、64 位 ID、位置、局部索引、湿权重、CFL 和失败类别，再全局终止。

`bomCheckEverySubstep=.FALSE.` 只能减少昂贵的全局预算频率，不能关闭数值安全检查。

### 6.4 `BOM_CHECK_STATE`

冻结逻辑接口为：

```text
BOM_CHECK_STATE(checkTime, checkIter, checkContext, myThid)
```

完整预算必须精确验证：每 tile 的 `bomNPartTile` 在容量内；有效槽紧凑且尾槽仍为 `BOM_UNUSED/id=0`；有效 ID 为正；全局 owner 总数等于 `bomNPartExpected`；全局 ID 无重复；状态只为 ALIVE/WAITING；坐标、release、age 和诊断字段有限；age 非负；WAITING 的 age 为 0 且 release 晚于 `checkTime`，ALIVE 的 release 不晚于 `checkTime`（均使用同一 `timeTol`）；每个有效位置仍由记录 tile 唯一拥有并有有效湿 stencil。

P1.3 的全局 ID 检查上限为已有 `bomInitGlobalLimit<=bomMaxInitRecords`，使用 schema 1 同义的两个 32 位 word 做可移植 collective gather 后精确排序/比较，不能用可能碰撞的浮点和、XOR 或哈希代替。`bomCheckEverySubstep=.TRUE.` 时每个 nominal 子步末执行；为 `.FALSE.` 时只跳过中间完整预算，海洋步末仍无条件执行。

I05/I06 固定使用同一个全湿 Cartesian 中央 C 点 `(xRef,yRef)`，令 `T=deltaTClock`、`Lx=dxF(iRef,jRef)`、`Ly=dyF(iRef,jRef)`，从 `x0=xRef,y0=yRef` 积分冻结仿射场：

```text
dx/dt = u0 + ax*(x-xRef),  u0=0.04*Lx/T, ax= 0.20/T
dy/dt = v0 + ay*(y-yRef),  v0=0.03*Ly/T, ay=-0.15/T
x(T) = xRef + (u0/ax)*(exp(ax*T)-1)
y(T) = yRef + (v0/ay)*(exp(ay*T)-1)
```

四个固定子步尺度为 `T/4,T/8,T/16,T/32`，风为零。verification override 按 C 点原生坐标填充该仿射场，使 P1.2 双线性插值在解析上精确。fixture 必须预先证明全部 stage 留在同一 owner tile、最近 C 点度量有效且 CFL 低于阈值；最细两组观测阶按前述范围验收，运行后不得改系数、步长或阈值迎合结果。

## 9. 当前已知风险

- EXF 风虽在格心且为 east/north，仍必须先复制到 BOM 快照，避免积分阶段依赖外部 COMMON 的更新时序；其标签是本海洋步 `LOAD_FIELDS_DRIVER` 的请求时刻 `t0`，不是 BOM 调用时刻 `t1`；
- 固定步末场使真实时变问题的总体时间精度受场冻结限制，RK 收敛只能在稳态/解析 fixture 上裁决积分器实现；
- P1.3 的严格 owner 检查会拒绝靠近 tile 边界的合法物理轨迹，这是工作包边界而非最终功能；
- `dtGuard`、球面坐标率和局地物理网格尺度混用会导致 CFL 错判，门禁必须同时覆盖 Cartesian 与非零纬度球面配置；
- release 落在端点附近时可能受浮点表示影响，必须固定尺度化时间容差并覆盖起点/内部/终点三类边界；
- 调试编译器可能在自定义非有限检查前触发浮点 trap，负测驱动必须同时验证错误上下文，不能只看退出码。
