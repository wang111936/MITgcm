# MITGCM-BOM P2.0 slow-manifold interface freeze

Status: **FROZEN FOR P2.1--P2.5 IMPLEMENTATION; PRODUCTION FORTRAN UNCHANGED**

This document is normative for Phase 2. If an implementation needs a
different formula, time label, source policy, schema, or failure meaning, the
change must first be reviewed here and propagated to the requirement and test
documents. Passing tests by silently changing this contract is prohibited.

## 1. Scope and compatibility boundary

Phase 2 adds only single-clump slow-manifold physics:

- `bomMode='BOM'` becomes executable;
- `bomEquationMode='PAPER2024'` is the production default;
- `bomEquationMode='JULIA'` preserves the locked Julia algebra for controlled
  comparisons;
- `LEEW` retains its accepted Phase-1 equation, field-time behavior, output,
  owner migration, and restart semantics unless a later explicitly tested
  migration changes its schema wrapper;
- `EBOM` and `EBOMB`, springs, neighbors, biology, beaching transitions,
  random events, OpenMP production, EXCH2/general grids, changed-decomposition
  restart, target-server optimization, and two-way ocean feedback remain out
  of scope.

The P2.1 PR may add endpoint state and providers only. P2.2 adds derivative
kernels. P2.3 adds the stateless equation modes. P2.4 connects stage time and
golden tests. P2.5 performs output/restart/MPI integration and full closeout.
No PR may skip this order.

## 2. Authority and notation

Priority is:

1. Bonner, Beron-Vera, and Olascoaga (2024), arXiv `2410.01468v1`, for
   `PAPER2024`;
2. `SargassumBOMB.jl@156557359185e4413ce82829f3ed26a4eb8c6283` for
   `JULIA`;
3. MITgcm for time, grid metrics, mask, MPI, and I/O;
4. this document for explicit engineering choices and failure behavior.

All calculation fields are east/north and SI:

- position labels are metres for Cartesian and degrees for spherical-polar;
- velocities are m s^-1;
- spatial velocity gradients and vorticity are s^-1;
- material derivatives are m s^-2;
- `fCori` is s^-1;
- inertial response `bomTau` is seconds.

Let `vBase` mean the supplied ocean current. It is Eulerian when
`bomCurrentPolicy='EULERIAN'` and a declared precombined current when the
policy is `PRECOMBINED`. Define

```text
v = vBase + bomSigma*vS      (explicit-source policy)
v = vBase                    (precombined policy)
u = (1-bomAlpha)*v + bomAlpha*vW
```

`vS` is explicit Stokes and `vW` is 10 m wind.

## 3. Runtime parameter contract

Existing names keep their Phase-1 meaning. The following Phase-2 parameters
are added without aliasing `bomLeewayWindCoeff`:

| Parameter | Runtime type | Default | Legal contract |
|---|---|---:|---|
| `bomEquationMode` | character | `PAPER2024` | `PAPER2024` or `JULIA` with `BOM` |
| `bomStokesSource` | character | `NONE` | `NONE`, `FILES`, or compiled `COUPLER` |
| `bomCurrentPolicy` | character | `UNSET` | must be explicitly `EULERIAN` or `PRECOMBINED` with `BOM` |
| `bomAlpha` | `_RL` | 0 | finite, `0 <= value <= 1`, dimensionless |
| `bomTauDays` | `_RL` | 0 | finite, nonnegative days; converted once |
| `bomR` | `_RL` | 1 | finite, `0 < value <= 1` |
| `bomSigma` | `_RL` | 0 | finite, nonnegative; only scales explicit Stokes |
| `bomUStokesFile` | filename | blank | required with `FILES` |
| `bomVStokesFile` | filename | blank | required with `FILES` |
| `bomStokesStartTime` | `_RL` | 0 | finite model seconds |
| `bomStokesPeriod` | `_RL` | 0 | positive seconds with `FILES` |
| `bomStokesRepCycle` | `_RL` | 0 | zero or finite and not shorter than the period |
| `bomStokesInScale` | `_RL` | 1 | finite conversion to m s^-1 |
| `bomStokesFilePrec` | `INTEGER` | 64 | `32` or `64`; recorded in the manifest |

`bomTau=86400*bomTauDays` is computed once with overflow and finite checks.
The RHS never contains a day conversion constant. The paper reference values
used by B16 are `alpha=3.37e-3`, `tauDays=0.0103`, `R=0.823`, and
`sigma=1.2`; they are test values, not universal production defaults.

Mode constraints:

- `bomCurrentPolicy='UNSET'` or an unknown value is fatal with `BOM`; a
  false-like default is never treated as an explicit scientific declaration;
- `LEEW` continues to use `bomLeewayWindCoeff`; the Phase-2 parameters do not
  alter its RHS;
- `BOM` accepts RK2 or RK4 and requires the endpoint interface;
- `bomWindSource='NONE'` requires `bomAlpha=0`; `EXF` requires the existing
  compile/runtime EXF dependencies;
- `EBOM` and `EBOMB` remain fatal in Phase 2;
- no separate Earth-rotation parameter is introduced: the model uses
  MITgcm `fCori` at the particle stage position.

## 5. Exact time bracket

For `BOM_MAIN(myTime,myIter,myThid)`:

```text
t0    = myTime - deltaTClock
t1    = myTime
iter0 = myIter - 1
iter1 = myIter
```

The bracket is valid only when:

- all four labels are representable and consistent;
- `t1>t0` and `t1-t0` equals `deltaTClock` within the existing scaled
  time-nearness convention;
- on every step after initialization or restart, the previously accepted
  endpoint 1 equals the new `(t0,iter0)`;
- every required source supplies both exact endpoint values;
- all wet values, metrics, and halos are finite and source-valid.

Fresh initialization publishes the model state at `(startTime,nIter0)` as
both endpoints and marks the bracket as single-time initialization. The first
step replaces endpoint 1 with `(t1,iter1)`. A restart restores the saved
schema-2 bracket before the next step.

The build transaction is:

1. validate incoming labels and previous endpoint continuity;
2. copy the accepted endpoint 1 into scratch endpoint 0;
3. evaluate all required providers at exact `t1` into scratch endpoint 1;
4. rotate/colocate, mask, exchange halos, and validate scratch values;
5. globally reduce errors;
6. commit both scratch endpoints and labels once, then set `bomEnvReady`;
7. leave accepted state unchanged on any component-test failure.

The production model stops after a fatal failure; the no-partial-commit rule
is still tested in component drivers.

## 6. Source-provider contracts

### 6.1 Base ocean current

At initialization and every new endpoint, copy surface `uVel/vVel` into true
single-level work arrays, call `ROTATE_UV2EN_RL` with the accepted Phase-1
arguments, and exchange the resulting east/north scalars. The new endpoint
at a normal `BOM_MAIN` call is the post-step ocean state `(t1,iter1)`.

### 6.2 EXF wind

The EXF provider evaluates `uwind/vwind` at exact BOM endpoint time into
BOM-owned arrays. It may reuse EXF record timing and read/interpolation
helpers, but it must not:

- change global `uwind/vwind` or `uwind0/uwind1/vwind0/vwind1`;
- assume raw EXF record 0/1 equal `t0/t1`;
- use the Phase-1 currently visible `uwind/vwind` as the new endpoint;
- silently extrapolate beyond configured EXF coverage.

`NONE` publishes exact zero arrays and valid wet masks. `EXF` requires
`ALLOW_EXF`, `useEXF`, `useAtmWind`, paired U/V coverage, SI scaling, and an
exact evaluation for both endpoints.

### 6.3 Stokes

| `bomStokesSource` | Owner | Update contract | Failure contract |
|---|---|---|---|
| `NONE` | BOM | publish exact zero at both endpoints | nonzero sigma is fatal |
| `FILES` | BOM file provider | evaluate paired U/V files at exact endpoint times | blank file, bad period, missing record, bad unit/finite/mask is fatal |
| `COUPLER` | external producer, BOM validates | producer publishes the exact requested label before its field commit | absent hook, stale/future label, partial component, or invalid field is fatal |

The FILES layout follows MITgcm global 2-D time-record conventions and
BOM-owned interpolation. The two filenames, start time, period, repeat cycle,
input scale, precision/layout metadata, and checksums enter the run manifest.
P2.1 may reuse a general reader, but may not make EXF a mandatory dependency
for `FILES` unless that dependency change is separately reviewed.

The COUPLER setter copies into BOM-owned scratch buffers; it never keeps a
pointer or alias to producer memory. Selection is legal only when the provider
hook is compiled and the requested endpoint publication is complete. The
accepted old endpoint is reused transactionally; providers do not relabel it.

## 7. Stokes de-duplication and diagnostics

The only legal policy matrix is:

| `bomCurrentPolicy` | source | sigma | resulting `v` |
|---|---|---:|---|
| `EULERIAN` | `NONE` | 0 | `vBase` (Eulerian only) |
| `EULERIAN` | `FILES`/available `COUPLER` | finite and nonnegative | `vBase+sigma*vS` |
| `PRECOMBINED` | `NONE` | 0 | `vBase` (declared precombined) |

All other combinations are fatal. An active explicit source with sigma zero
is legal for controlled A/B and source-interface tests but prints an
informational zero-effect diagnostic. It is not a substitute for the
mandatory duplicate declaration.

At startup print and record:

```text
current-policy, stokes-source, sigma, wind-source,
equation-mode, t0/t1 availability, file/provider identity
```

Trajectory/pickup metadata uses `EULERIAN_EXPLICIT`, `EULERIAN_ONLY`, or
`PRECOMBINED` rather than always labeling `vBase` as Eulerian.

## 8. Time interpolation

For stage time `ts`, define

```text
theta = (ts-t0)/(t1-t0)
F(ts) = (1-theta)*F0 + theta*F1
dtF   = (F1-F0)/(t1-t0)
```

A stage within the scaled endpoint tolerance is snapped to exactly 0 or 1.
A stage outside the bracket is fatal; no clamping or extrapolation is allowed.
Values, first spatial derivatives, and validity masks use the same stage
position and endpoint contract. Since the spatial derivative operator is
linear, derivatives may be computed at endpoints and interpolated in time.
Nonlinear covariant products are formed only after stage-time interpolation.

RK2 uses times `t`, `t+h/2`, and final diagnostic time `t+h`. RK4 uses
`t`, `t+h/2`, `t+h/2`, `t+h`, and final diagnostic time `t+h`. Exact release
splitting passes the active interval start as the first stage time.

Linear endpoint interpolation limits the environmental representation to
second order in ocean endpoint spacing. RK4 remains fourth order for a fixed
smooth stage-evaluable RHS, but Phase 2 makes no fourth-order end-to-end claim
when the ocean/forcing endpoint spacing is refined. B05 tests these two claims
separately.

## 9. Spatial derivatives and spherical metrics

Derivatives are taken after C-grid rotation/colocation, in physical east and
north directions. `xC/yC` differences are never used as metres.

For a center with west/east separations `hW=dxC(i,j)` and
`hE=dxC(i+1,j)`, the second-order nonuniform central derivative is

```text
[-hE/(hW*(hW+hE))]*qW
+[(hE-hW)/(hW*hE)]*qC
+[hW/(hE*(hW+hE))]*qE
```

The north/south formula uses `dyC` analogously. If one centered neighbor is
dry or unavailable, a three-point second-order one-sided Lagrange derivative
may be used only when the center and next two points in that direction are
wet, available, and finite. Otherwise `bomGradValid` is false. No derivative
crosses land and no missing field is replaced by zero.

On Cartesian grids:

```text
tauSphere = 0
```

On supported unrotated spherical-polar grids:

```text
tauSphere = tan(latitude)/rSphere
```

`dxC/dyC` already incorporate physical metric distance, so no additional
`gammaSphere^-1` multiplies east derivatives. The existing native-coordinate
conversion applies `1/(rSphere*cos(latitude))` only when converting the final
eastward velocity to longitude rate.

All used `dxC`, `dyC`, `fCori`, `rSphere`, latitude, cosine, tangent, fields,
and derivative coefficients must be finite; distances and `rSphere` must be
positive. The Phase-1 near-pole rejection remains. The same wet/valid weights
are used for every component interpolated to one particle stage.

## 10. Covariant operators

For a stage vector `w=(wE,wN)`:

```text
DselfE(w) = dt(wE) + wE*dE(wE) + wN*dN(wE)
                         - tauSphere*wE*wN
DselfN(w) = dt(wN) + wE*dE(wN) + wN*dN(wN)
                         + tauSphere*wE*wE
vort(w)   = dE(wN) - dN(wE) + tauSphere*wE
wPerp     = (-wN,wE)
```

Every multiplication and addition is finite-checked before publication to an
RHS candidate. The derivative kernel returns values plus validity; it never
changes particle state.

## 11. `PAPER2024` RHS

At the same stage position and time:

```text
v     = vBase + sigma*vS            # or declared precombined vBase
u     = (1-alpha)*v + alpha*vW
Dv    = Dself(v)
Du    = Dself(u)
omega = vort(v)
cV    = f + omega/3
cU    = f + tauSphere*uE + R*omega/3

inertE = R*DvE - R*cV*vN - DuE + cU*uN
inertN = R*DvN + R*cV*vE - DuN - cU*uE
driftE = uE + tau*inertE
driftN = uN + tau*inertN
```

This is paper equation (2b) with no spring force. The metric square root is
implemented once by converting final east/north drift to the native position
rate. It is not multiplied into `inertE/inertN`.

## 12. `JULIA` RHS

The compatibility mode reproduces the locked source evaluation order:

```text
DvBase = Dself(vBase)
DvS    = Dself(vS)
DvW    = Dself(vW)
v      = vBase + sigma*vS
Dv     = DvBase + sigma*DvS
u      = (1-alpha)*v + alpha*vW
Du     = (1-alpha)*Dv + alpha*DvW
omega  = vort(vBase)
```

The final `cV`, `cU`, inertial terms, and drift use the same component signs
as section 11. This mode intentionally omits cross-advection terms and
explicit-Stokes vorticity because the locked Julia source does so. It is not
the production default and never silently replaces `PAPER2024`.

A discriminating fixture with nonparallel gradients must make the two modes
differ by much more than their numerical tolerance. A fixture on which they
accidentally agree cannot validate the mode switch.

## 13. Stateless RHS and transactional integration

The Phase-2 RHS accepts, at minimum:

```text
x, y, stageTime, trialDt, owner bi/bj, equationMode
```

and returns native coordinate rates, component diagnostics, local indices,
wet/valid weights, CFL, owner/stencil state, stable stage/failure codes, and a
single validity flag. It writes no COMMON particle field and changes no owner
count.

RK stage routines pass exact stage time and retain the Phase-1 candidate
transaction. A failed K1--K4 or FINAL diagnostic refresh leaves position,
status, age, index, and every velocity/derivative diagnostic unchanged.
Owner migration remains after a successfully committed complete substep.
CFL uses the final total drift magnitude at every trial stage, not only `u`
or the Eulerian current.

## 14. Stable failures and stages

Existing codes 0--8 and stage values 0--5 are immutable. Append:

```text
BOM_FAIL_FIELD_TIME       = 9
BOM_FAIL_FIELD_SOURCE     = 10
BOM_FAIL_METRIC           = 11
BOM_FAIL_GRADIENT         = 12
BOM_FAIL_EQUATION         = 13
BOM_FAIL_STOKES_DUPLICATE = 14
BOM_FAIL_PICKUP_SCHEMA    = 15

BOM_STAGE_FIELD_OLD       = 6
BOM_STAGE_FIELD_NEW       = 7
BOM_STAGE_DERIVATIVE      = 8
```

A field-build error reports source and endpoint stage. A particle RHS error
reports its RK stage plus the Phase-2 failure code. The first failure in one
trial is retained according to this priority:

```text
state/time -> source/de-dup -> map/owner/stencil -> metric/gradient
-> interpolation -> equation finite/range -> CFL -> final candidate
```

Setup and pickup failures may stop before a particle ID exists; particle
failures include time, iteration, substep, rank/tile/slot, ID, stage/code,
position, local index, wet weight, CFL, source policy, and equation mode.

## 15. Diagnostics and trajectory schema 2

For `BOM` mode, the accepted final-position diagnostic candidate contains:

```text
vBaseE/N, vSE/N, vWE/N, vE/N, uE/N,
DvE/N, DuE/N, omega, f, tauSphere,
inertialE/N, driftE/N, equationMode, currentPolicy
```

Trajectory schema 2 adds these quantities or a documented subset sufficient
to reconstruct every RHS term. Units and time labels are explicit. Existing
schema-1 fields and exact two-word IDs retain their order or are migrated by a
versioned reader; a file is never reinterpreted under a new schema number.

## 16. Pickup schema 2

Schema 2 retains all Phase-1 particle/output fields and adds:

- mode, equation mode, current policy, wind/Stokes source codes;
- `alpha`, SI `tau`, `R`, `sigma`, and an exact parameter fingerprint;
- both accepted endpoint times, iterations, readiness and source availability;
- endpoint east/north fields for all three sources and the validity state;
- enough file/coupler provider identity to reject a changed source;
- decomposition signature and existing output schedule.

Endpoint gradients may be saved or deterministically rebuilt from saved
endpoint fields; the selected strategy is fixed in P2.1 before schema-2 files
are produced. In either case continuous versus restart values must be bitwise
identical for the same decomposition.

Read policy:

- schema 2: require exact mode/source/parameter/decomposition fingerprint,
  validate all scratch data and global IDs, then commit once;
- schema 1 with `LEEW`: allowed migration path, preserving Phase-1 behavior;
- schema 1 with `BOM`: fatal `BOM_FAIL_PICKUP_SCHEMA` before particle commit;
- unknown/newer schema or changed equation/source policy: fatal;
- changed decomposition remains unsupported in Phase 2.

P2.4 creates, but P2.0 predefines, these versioned files:

```text
verification/bom/reference/phase02/input_fields_v1.csv
verification/bom/reference/phase02/input_particles_v1.csv
verification/bom/reference/phase02/input_parameters_v1.toml

verification/bom/reference/phase02/golden_rhs_julia_v1.csv
verification/bom/reference/phase02/golden_traj_julia_rk2_v1.csv
verification/bom/reference/phase02/golden_traj_julia_rk4_v1.csv
```

The fixture is Cartesian, all wet, 400 km by 300 km, uses three particles,
`t=0..86400 s`, fixed `dt=900 s`, constant
`f=2.18213/86400 s^-1`, and the paper Table-2 values listed in section 3.
Base, Stokes, and wind fields are distinct affine functions of x, y, and t
with nonparallel gradients, so `PAPER2024` and `JULIA` cannot accidentally
coincide. P2.4 freezes exact coefficients before generating output and may not
change them after observing a mismatch.

The Julia generator uses Julia 1.10.12, the project-locked rebuilt Manifest,
the locked source commit, and a fixed-step RK2/RK4 oracle. Adaptive Tsit5 output is recorded only
as non-gating context. File and environment checksums are validated before
each B16 run. `REFERENCE_LOCK.md` remains `PROVISIONAL` until these files are
generated, reviewed, and executed successfully.

## 18. Design decisions

| ID | Decision |
|---|---|
| P2-D001 | Only `BOM` is enabled in Phase 2; LEEW remains the regression baseline and EBOM/EBOMB remain deferred. |
| P2-D002 | Every required field is evaluated at exact BOM model endpoints in BOM-owned storage. |
| P2-D003 | Raw EXF record endpoints are never relabeled as BOM endpoints. |
| P2-D004 | The supplied-current Stokes declaration is mandatory and illegal combinations are fatal. |
| P2-D005 | `PAPER2024` forms material derivatives and vorticity from combined total fields. |
| P2-D006 | `JULIA` preserves weighted per-source derivatives and base-current vorticity from the locked source. |
| P2-D007 | Physical C-center separations define derivatives; degree differences never enter SI gradients. |
| P2-D008 | Nonuniform three-point second-order formulas are used; derivatives never cross land. |
| P2-D009 | Spherical covariant terms use `tan(latitude)/rSphere`; east metric and native coordinate conversion are each applied once. |
| P2-D010 | `fCori` is the only Coriolis source. |
| P2-D011 | Nonlinear covariant products are formed after stage-time interpolation. |
| P2-D012 | Linear endpoint interpolation caps the environmental representation at second order in endpoint spacing. |
| P2-D013 | Existing failure/stage codes remain stable; Phase-2 codes append without reuse. |
| P2-D014 | Endpoint publication and particle substeps are separate transactions. |
| P2-D015 | Schema 2 saves both accepted endpoint histories; schema 1 cannot start BOM inertia. |
| P2-D016 | B16 uses locked fixed-step Julia oracles; adaptive Tsit5 is non-gating. |
| P2-D017 | `bomTauDays` is converted once to SI; all kernels are SI-only. |
| P2-D018 | Target-server optimization remains Phase 5 and does not weaken local correctness gates. |
