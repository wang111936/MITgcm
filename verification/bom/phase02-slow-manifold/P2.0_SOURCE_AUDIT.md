## 2. Current implementation facts

1. `BOM_MAIN(myTime,myIter)` is called after the MITgcm time counter has
   advanced. It integrates `[myTime-deltaTClock,myTime]`.
2. Phase 1 constructs the ocean field from post-step `uVel/vVel`, so that
   field is labeled `(myTime,myIter)`.
3. `LOAD_FIELDS_DRIVER` calls EXF before the ocean step, so the `uwind/vwind`
   visible to the Phase-1 BOM call were requested at
   `(myTime-deltaTClock,myIter-1)`.
4. EXF `uwind0/uwind1` are the previous and next *forcing records* used to
   interpolate the current forcing. They are not generally the two BOM ocean
   step endpoints and must not be relabeled as such.
5. Phase-1 RK routines do not accept stage time; they evaluate one frozen
   field. P2.1 must change the internal RHS/RK contract before any claim about
   time-dependent accuracy.
6. Pickup schema 1 restores particles and the output schedule but has no
   environment bracket. A BOM inertial restart from schema 1 therefore cannot
   reproduce a continuous first post-restart material derivative.
7. `dxC/dyC` are physical C-center separations in metres. `xC/yC` are only
   coordinate labels and are degrees on spherical-polar grids; derivatives
   must use the metric separations, not differences of `xC/yC`.
8. `MOM_CALC_RELVORT3` returns corner vorticity from native staggered U/V.
   Phase 2 needs derivatives of already colocated east/north C-point total
   velocity, so direct reuse would change location and omit explicit Stokes.

## 3. Paper equation finding

With east/north physical components, define

```text
v = vBase + sigma*vS
u = (1-alpha)*v + alpha*vW
```

where `vBase` is Eulerian unless the run explicitly declares that it already
contains Stokes. For any vector field `w=(wE,wN)`, the paper covariant
self-material derivative in physical east/north coordinates is

```text
DselfE(w) = dt(wE) + wE*dE(wE) + wN*dN(wE) - tauSphere*wE*wN
DselfN(w) = dt(wN) + wE*dE(wN) + wN*dN(wN) + tauSphere*wE*wE
vort(w)   = dE(wN) - dN(wE) + tauSphere*wE
```

with `tauSphere=tan(latitude)/rSphere` on the supported unrotated spherical
grid and zero on Cartesian grids. Since `dE` is already a physical eastward
derivative, the paper's separate `gammaSphere^-1` factor is not applied a
second time. Native-coordinate rate conversion remains in the existing BOM
coordinate-update layer.

The default mode must compute `Dv=Dself(v)`, `Du=Dself(u)`, and
`omega=vort(v)` from the combined fields. This is the direct interpretation
of paper equations (1), (2b), (B.7), and (B.11).

## 4. Locked Julia behavior finding

The locked Julia `Raft!` performs a different sequence:

```text
v       = vBase + sigma*vS
DvJulia = Dself(vBase) + sigma*Dself(vS)
u       = (1-alpha)*v + alpha*vW
DuJulia = (1-alpha)*DvJulia + alpha*Dself(vW)
omega   = vort(vBase)
```

The reference therefore omits cross-advection terms created by combining
the component fields, and its vorticity excludes explicit Stokes. These are
observable differences whenever the fields have nonzero, nonparallel spatial
gradients. They are not roundoff variants and must not be hidden behind one
implementation.

The remaining component signs agree with the paper when
`wPerp=(-wN,wE)`: the x component contains the negative v-y rotation and
positive u-y rotation, while the y component contains the positive v-x and
negative u-x rotations. Julia's `1/gammaSphere` x-coordinate factor is a
coordinate-rate conversion, not another physical acceleration term.

## 5. Frozen equation-mode resolution

| Concern | `PAPER2024` | `JULIA` |
|---|---|---|
| combined ocean material derivative | self derivative of total `v` | weighted per-source self derivatives |
| carrying-flow material derivative | self derivative of total `u` | weighted `DvJulia` plus wind self derivative |
| vorticity | total `v` | `vBase` only |
| component rotation signs | paper equation (2b) | same signs |
| spherical coordinate rate | MITgcm native conversion | same conversion after Julia algebra |
| production default | yes | no; compatibility and B16 only |

Both modes use SI internally, MITgcm `fCori`, the same endpoint interpolation,
the same owner/mask rules, and the same RK method. `JULIA` does not promise
bitwise equivalence with the package's adaptive Tsit5 trajectory.

## 6. Stokes ownership finding

The numerical formula cannot detect whether a supplied ocean product already
contains Stokes drift. The run must declare this fact. The only safe matrix is:

| `bomCurrentPolicy` | explicit source | `bomSigma` | decision |
|---|---|---:|---|
| `EULERIAN` | `NONE` | 0 | valid Eulerian-only ocean |
| `EULERIAN` | `FILES` or available `COUPLER` | finite, nonnegative | valid explicit composition |
| `PRECOMBINED` | `NONE` | 0 | valid precombined current |
| `PRECOMBINED` | `FILES`/`COUPLER` | any | fatal duplicate risk |
| either declared policy | `NONE` | nonzero | fatal unused/ambiguous factor |
| `UNSET` or unknown | any | any | fatal missing/invalid declaration |

No heuristic based on field magnitude, filename, or metadata guess is
acceptable. The declaration, source, sigma, and final policy are written to
stdout, trajectory metadata, and pickup fingerprint.

## 7. Endpoint and restart finding

The exact model bracket is always
`t0=myTime-deltaTClock`, `t1=myTime`, with iteration labels
`myIter-1` and `myIter`. Every source provider must publish values evaluated
at those exact times into BOM-owned arrays. In particular, the EXF provider
may reuse EXF timing and readers but may not mutate or relabel global EXF
working arrays.

At a normal step boundary the module retains both accepted endpoints. On the
next step, endpoint 1 must equal the new `t0` before it is shifted to endpoint
0 and the new endpoint 1 is built. Pickup schema 2 saves both endpoint arrays,
times, iterations, availability, source policy, and parameter fingerprint.
This is larger than saving one endpoint but gives a directly auditable restart
transaction and matches the frozen Phase-2 stage record.

Schema 1 may be read only for a continuing `LEEW` run. It is rejected for
`bomMode='BOM'` because the missing bracket cannot be reconstructed without
changing the first post-restart derivative.

## 8. Metric and mask finding

Phase-2 derivatives are C-point derivatives of colocated east/north fields.
For nonuniform regular grids the central and one-sided formulas must use the
actual adjacent `dxC/dyC` separations and second-order three-point Lagrange
coefficients. Differentiation across land is forbidden. A centered stencil is
preferred; a second-order one-sided all-wet stencil is permitted; otherwise
the point is marked derivative-invalid. A particle stencil that needs an
invalid wet point fails rather than extrapolating or silently beaching.

All used metric values, `fCori`, `rSphere`, latitude, `cos(latitude)`, and
derived `tan(latitude)/rSphere` must be finite. The existing Phase-1 polar
exclusion remains in force. EXCH2, rotated, general curvilinear, and OpenMP
production support remain out of Phase 2.

## 9. Closed findings and decision

| Finding | Frozen resolution |
|---|---|
| ocean and wind currently carry different time labels | exact BOM-owned `t0/t1` evaluation for every source |
| EXF record endpoints could be mistaken for model endpoints | provider evaluates exact times; never relabel raw EXF records |
| paper and Julia material derivatives differ | separate named algebra paths with a discriminating test |
| explicit Stokes could be counted twice | mandatory declaration and fatal configuration matrix |
| degree differences could be used as metres | derivatives use `dxC/dyC`; native coordinate update remains separate |
| corner vorticity could be reused at the wrong location | dedicated C-point total-field derivative/vorticity kernel |
| a bad field build could partially publish state | scratch build, global validation, one bracket commit |
| a bad RK stage could partially move a particle | retain Phase-1 per-particle transactional candidate contract |
| schema-1 restart lacks field history | reject for BOM; migration allowed only for unchanged LEEW |
| RK4 could be advertised as fourth order for sampled forcing | B05 separately measures integrator order and endpoint-sampling order |
