# MITGCM-BOM P4.0 biology, land and event interface freeze

Status: **FROZEN FOR P4.1--P4.5 IMPLEMENTATION**

Baseline: MITGCM-BOM-v0.4 / commit
70c02a277ea7d472ccf6e9a7533b2b41ed7eab5a

Target: MITGCM-BOM-v0.5

## 1. Scope and compatibility boundary

Phase 4 adds only:

- transactional temperature and nutrient endpoints;
- a stateless Brooks growth-rate kernel and fixed-substep amount update;
- explicit boundary, terminal and biology state transitions;
- compact-tail O(1) slot reuse;
- deterministic wet-placement retries, counter RNG and birth IDs;
- versioned event records, event budgets and grid/counter diagnostics;
- biology-aware migration, container schema 4 and same-decomposition pickup;
- direct B11--B15, B17--B19 evidence and the complete predecessor gate.

Phase 4 does not add:

- nutrient or heat consumption by particles;
- momentum, temperature or tracer feedback to MITgcm;
- sinking, resuspension or three-dimensional particles;
- an adaptive particle integrator;
- OpenMP-safe concurrent event allocation;
- target-server 100,000-particle scaling;
- changed-decomposition pickup;
- EXCH2, cubed-sphere, LLC or general-curvilinear support.

All P4 controls default disabled. With bomUseBiology=.FALSE. and
bomUseLand=.FALSE., the exact released v0.4 path, arithmetic, collectives,
schemas and failure behavior remain selected. P4.0 itself is documentation
only and changes no production source, build input or executable test driver.

### 3.1 Switches and sources

| Parameter | Type | Frozen meaning |
|---|---|---|
| bomUseBiology | logical | enable T/N Brooks update and biological birth/death |
| bomUseLand | logical | classify land and open-boundary terminal events |
| bomTempSource | character | NONE or THETA |

When biology is enabled:

- bomTempSource must be THETA;
- bomNSource must be PTRACER or FILES;

- missing policy NO_GROWTH sets only the growth term to zero while mortality
  remains active and records a missing-growth diagnostic.

NO_GROWTH is not permission to replace finite negative N, file gaps or bad
temperature with arbitrary values. Finite N is clamped to max(N,0). A source
configuration error always stops before state publication.

## 6. Authoritative state and compact-tail free stack

P4 adds to each owner record:

| Field | Type | Meaning |
|---|---|---|
| bomParentId | INTEGER*8 | exact parent ID; zero for initial owners |
| bomS | _RL | current amount |
| bomBirthCount | INTEGER | count of successful children from this owner |

P4 adds global deterministic state:

| Field | Type | Meaning |
|---|---|---|
| bomNextId | INTEGER*8 | next contiguous birth ID |
| bomEventTimeIndex | INTEGER*8 | count of completed event phases |
| cumulative event counters | INTEGER*8 | accepted births, deaths, beaching, outside and cancellations |

Post-event owner storage remains compact:

    valid owners = slots 1:bomNPartTile
    free slots   = slots bomNPartTile+1:bomMaxPartTile

Every free slot has status UNUSED, ID zero, parent zero, birth count zero and
finite zeroed real state. The explicit free stack lists only that free tail.
Its top pop must return bomNPartTile+1. The stack is deterministic derived
state and is rebuilt after initial read, owner migration and pickup.

Deletion is O(1):

1. copy the final valid owner into the removed slot when they differ;
2. clear the former final slot;
3. decrement bomNPartTile;
4. push the cleared tail.

Allocation is O(1):

1. pop the next tail;
2. require it equals bomNPartTile+1;
3. write the complete candidate record;
4. increment bomNPartTile.

For several removals on one tile, the transaction first binds exact IDs to
current slots and applies removals in descending slot order. The physical slot
sequence is not observable identity. Output, RNG, event order and comparisons
use exact IDs.

## 7. Accepted temperature and nutrient endpoints

P4.1 adds OLD/NEW C-point arrays for temperature and nutrient, plus shared wet
validity, source metadata, exact times and iterations. Publication follows the
Phase 2 transaction:

1. build all scratch source fields and validity;
2. rotate or colocate only where required;
3. exchange scalar halos;
4. validate finite wet values, times and source completeness collectively;
5. publish the complete OLD/NEW bracket once;
6. on normal advance move accepted NEW to OLD only as part of the same
   transaction.

THETA copies only k=1 into a one-level work array. PTRACER copies only the
selected tracer at k=1 under its compile/runtime guard. FILES reads a
BOM-owned scalar record. No source memory is aliased.

Biology samples at the completed substep time tSub1 using the accepted
bracket and the same wet-weight interpolation policy as the physical
C-point pair. It does not sample T/N during RK K stages and does not compute
time derivatives of T or N.

The accepted OLD bracket, times, iterations, sources and validity enter
pickup. A restarted first biology event must receive bitwise-identical T/N
inputs to the continuous run under the same decomposition.

## 8. Stateless Brooks law

Let:

    Topt = (Tmin + Tmax) / 2

The temperature factor is evaluated by ordered branches:

| Condition | factor |
|---|---|
| T equals Tmin or Tmax | 0 |
| Tmin < T < Topt | exp(-0.5*((T-Topt)/(T-Tmin))^2) |
| T equals Topt | 1 |
| Topt < T < Tmax | exp(-0.5*((T-Topt)/(T-Tmax))^2) |
| otherwise | 0 |

Every input and intermediate is finite. Nsafe=max(N,0) and:

    nutrientFactor = Nsafe / (kN + Nsafe)
    dSdt = muMax * temperatureFactor * nutrientFactor - mortality
    Strial = Sbefore + dSdt * dtActive

The implementation uses overflow-safe ratios and additions. dtActive is the
same non-negative released-particle active duration accepted by movement for
the complete substep. A still-WAITING particle receives no biology update.

Thresholds are strict:

- Strial<Smin proposes DEAD_BIO;
- Strial>Smax proposes one birth;
- equality publishes Strial and creates no event;
- otherwise publishes Strial.

For death, the event records Strial and the owner is released at commit.
For a successful birth, parent and child both receive S0 and the parent's
birth count increases exactly once. For a placement cancellation, the parent
retains Sbefore and its birth count does not change.

## 9. Boundary classification and no-land-penetration rule

Boundary classification is enabled only by bomUseLand.

An attempted coordinate is:

- OUTSIDE when it is finite but outside a supported non-periodic global
  horizontal boundary;
- BEACHED when it maps uniquely inside the supported domain and its containing
  surface C cell is dry;
- WET when it maps uniquely to a wet containing C cell and the required
  interpolation predicate is valid;
- FATAL when coordinates, mapping, metric, ownership or masks are ambiguous
  or non-finite.

Periodic X is normalized before classification and cannot create OUTSIDE in X.
The accepted event coordinate for BEACHED or OUTSIDE is the particle's last
accepted wet coordinate at substep start. The first attempted terminal
coordinate and RK stage are stored in scratch and later in the event record.
No dry or exterior coordinate enters authoritative owner state.

If a particle first encounters a valid terminal boundary during an RK stage:

1. mark a stage-local terminal candidate in ensemble/per-particle scratch;
2. freeze its later trial position at the substep-start wet coordinate;
3. contribute zero physical and spring rate for its remaining stages;
4. exclude it from later stage scratch graphs without changing owner arrays;
5. defer the status transition, count change and graph publication to the
   complete post-migration event transaction.

A numerical or mapping failure is never relabelled as beaching. With land
disabled, released v0.4 fatal behavior remains unchanged.

## 10. Event-phase ordering and transaction

For every completed BOM substep, the order is:

1. finish and validate the complete movement transaction;
2. publish accepted wet movement coordinates;
3. migrate authoritative owners;
4. collect boundary terminal candidates;
5. sample T/N and compute biology candidates for remaining ALIVE owners;
6. collect biological deaths;
7. sort prospective birth parents by exact global parent ID;
8. generate/retry wet child placements;
9. assign child IDs in the same global parent order;
10. preflight global live count, tile/rank storage, packets, event buffer,
    exact IDs and the candidate post-event graph;
11. select the global first failure;
12. on complete success, publish owner/free-stack/global counters/event
    buffer/post-event graph once;
13. validate the budget and increment bomEventTimeIndex once;
14. flush event shards only at a defined safe point.

No owner/free-stack/ID/counter/event-buffer mutation is permitted before step
12. Every candidate field is stored in bounded scratch. Any fatal result
leaves authoritative state, schedules, accepted T/N endpoints and unflushed
event buffer bitwise unchanged.

Land/outside and biological death of the same owner cannot both be accepted:
boundary classification precedes biology. A parent that dies cannot produce a
child. One parent can propose at most one child in one event phase.

## 11. Birth placement

The base RNG key is:

    (bomSeed, parentId, parentBirthCount, bomEventTimeIndex)

Retry attempt a=0:bomBirthMaxTry-1 is an additional counter. Candidate angle
is in the open-bin-centred representation of [0,2*pi):

    u = (word + 0.5) / 4294967296
    theta = 2*pi*u

The child is:

    xChild = xParent + bomSpringL*cos(theta)
    yChild = yParent + bomSpringL*sin(theta)

using the existing Cartesian or spherical native-coordinate conversion and
overflow guards. Every attempt passes the same WET predicate used for an
accepted owner, including unique owner location, surface mask and required
interpolation support.

The first valid attempt wins. If every attempt is land/outside, emit
BIRTH_CANCEL, preserve parent Sbefore and create no ID. A fatal geometric,
mapping or non-finite error stops; it is not a retry. Capacity is checked after
placement and is fatal, not a cancellation.

## 12. Portable counter RNG

P4 freezes Philox4x32-10 with published constants:

| Constant | Unsigned 32-bit value |
|---|---:|
| M0 | 3528531795 |
| M1 | 3449720151 |
| W0 | 2654435769 |
| W1 | 3144134277 |

All words are stored in INTEGER*8 values 0 through 4294967295. Low/high
32-bit multiplication is implemented with 16-bit limbs, so no signed
INTEGER*8 overflow is invoked. XOR and shifts operate on normalized words;
key additions are explicit modulo 2^32.

For counter words c0,c1,c2,c3 and key words k0,k1, one round is exactly:

    (hi0,lo0) = unsignedMulHighLow32(M0,c0)
    (hi1,lo1) = unsignedMulHighLow32(M1,c2)
    next0 = XOR(XOR(hi1,c1),k0)
    next1 = lo1
    next2 = XOR(XOR(hi0,c3),k1)
    next3 = lo0

After rounds 1 through 9, update k0=(k0+W0) modulo 2^32 and
k1=(k1+W1) modulo 2^32. Round 10 returns its four next words without a
further observable key update.

unsignedMulHighLow32 splits a=a0+65536*a1 and b=b0+65536*b1, with every
limb in 0:65535, then evaluates:

    p0=a0*b0; p1=a0*b1; p2=a1*b0; p3=a1*b1
    carry=floor(p0/65536)+mod(p1,65536)+mod(p2,65536)
    lo=mod(p0,65536)+65536*mod(carry,65536)
    hi=mod(p3+floor(p1/65536)+floor(p2/65536)
           +floor(carry/65536),4294967296)

All products and sums fit signed INTEGER*8. No wrapped signed multiplication
is permitted as a substitute.

The full input is mixed in two Philox calls:

1. derive key words from counter
   (parentIdLo,parentIdHi,parentBirthCount,seedWord) with fixed zero key;
2. generate the placement word from counter
   (eventIndexLo,eventIndexHi,attempt,0) with the derived key.

The derived key is (firstCallWord0,firstCallWord2). The placement word is
secondCallWord0. seedWord and other 32-bit counters are normalized modulo
2^32; positive IDs and event indices are split into exact low/high words.
Birth count and attempt must be in the unsigned 32-bit range.

Ten rounds are mandatory in both calls. No compiler random intrinsic, rank,
tile, slot, loop counter or message order enters the result. A verification
oracle stores exact output words and angles for boundary-valued keys.

## 13. Deterministic birth IDs

bomNextId is initialized to one greater than the maximum accepted initial ID.
It is positive, never decreases and is saved exactly in pickup.

After placement, all ranks exchange only bounded accepted birth-event metadata:

    parentId, parentBirthCount, eventTimeIndex, attempt,
    candidate position, destination owner key

The live particle set is never gathered. Every rank validates identical
metadata, sorts by parentId, rejects duplicate parents and assigns:

    childId = bomNextIdBefore + zeroBasedGlobalBirthOrdinal

The transaction checks signed 64-bit range before addition. On success:

    bomNextIdAfter = bomNextIdBefore + numberAcceptedBirths

An MPI rank exclusive prefix may optimize routing only after the global
parent-ID order is established. Rank order alone never defines IDs.

P4 uses a bounded allgather event implementation. total event metadata must
fit bomMaxEventBuffer; overflow is failure 30 with no partial event. Phase 5
may replace this with a distributed parent-ID sort while preserving exact
ordering and output.

## 14. Capacity semantics

bomMaxParticles limits simultaneous ALIVE plus WAITING owners globally, not
the number ever created. It must not exceed aggregate compile-time owner
capacity.

The event preflight calculates, before any commit:

- global owners before and after all terminal/birth events;
- each destination tile count after removals and insertions;
- owner migration/event packet counts;
- compact-tail free stack availability;
- event scratch and unflushed buffer counts;
- exact-ID and arithmetic bounds.

Any exceeded compile/runtime limit reports required and available counts with
rank/tile/event context and stops. No candidate is truncated and no later
parent is silently denied to satisfy a cap.

## 15. Graph and owner migration integration

Owner packet schema 3 extends released schema 2 with:

- exact parent ID high/low words;
- birth count;
- S.

Every sent record is complete and versioned. Packet schema 2 remains used
unchanged when P4 switches are off.

P4 biology fields do not enter the stage ghost packet because ghosts are
read-only position/status inputs. New owners enter a graph only after the
event transaction.

When springs are active, the candidate post-event owner set rebuilds the
affected cutoff graph and components before commit. The published raft ID is
again the minimum exact ID in the accepted component. A failed rebuild rolls
back the entire event phase. When springs are off, graph work is absent.

## 16. Initial, trajectory, event and pickup schemas

### 16.1 Initial schema 2

Biology-enabled runs require initial schema 2. It appends to schema-1 data:

- exact parent ID high/low words;
- S;
- birth count.

Initial parent zero is accepted. Nonzero parents must be positive, not equal
to the owner ID and refer to an earlier or externally documented lineage;
they need not be currently alive. S is finite and birth count non-negative.
Schema 1 remains exact for P4-disabled runs and is not silently promoted.

### 16.2 P4 trajectory sidecar

The required P4 sidecar schema 1 has four logical fields aligned one-to-one
with the schema-2 core owner order:

1. parent ID high word;
2. parent ID low word;
3. S;
4. birth count.

Exact integer words are range-checked before conversion to the existing real
record representation. Header/signature/time/iteration/tile/owner alignment,
length and checksums are mandatory.

### 16.3 Event schema 1

Each event record contains:

- schema and event type;
- exact eventTimeIndex and event time;
- MITgcm iteration and BOM substep;
- exact subject, parent and child IDs;
- old and new status;
- accepted and first attempted X/Y;
- Sbefore, Strial and Safter;
- retry attempt count;
- source and destination rank/tile keys.

Exact 64-bit values use high/low words. BIRTH uses subject=child and a
positive child ID. DEAD_BIO, BEACHED and OUTSIDE use subject=terminal owner
and child=0. BIRTH_CANCEL uses subject=parent and child=0.

Event files are per-rank append-only shards with a manifest of schema, source
head, parameter signature, time range, record count, file size and SHA-256.
Canonical verification sorts records by
(eventTimeIndex,eventType,subjectId,parentId).

### 16.4 Pickup schema 4

Pickup schema 4 retains released core/P2/P3 bytes and adds:

- P4 owner sidecar;
- exact bomNextId and bomEventTimeIndex;
- seed and cumulative event counters;
- P4 parameter/source/decomposition signature;
- accepted T/N OLD bracket, validity, times and iterations;
- compact-tail stack reconstruction signature;
- unflushed event records, or proof that a forced pre-pickup flush completed.

Neighbor and ghost arrays remain rebuildable and are not persisted. Same
decomposition is required. A continuous and split run must match owner state,
global counters, next IDs, events and subsequent output bitwise.

## 17. Diagnostics and budgets

Every successful event phase checks:

    aliveAfter = aliveBefore
                 + births
                 - biologicalDeaths
                 - beached
                 - outside

Cancellations do not change alive count. Additional invariants:

- every live/waiting owner ID is positive and globally unique;
- every parent ID is zero or a positive ID different from the child;
- bomNextId exceeds every allocated owner or child ID;
- all owner numeric fields are finite;
- all ALIVE owners occupy accepted wet coordinates;
- all free-tail slots are zero/UNUSED and stack-consistent;
- event records balance cumulative counters exactly;
- one eventTimeIndex value is consumed by each successful substep event phase,
  including a zero-event phase;
- graph/component invariants hold when springs are active.

Phase 4 provides counters/gridded diagnostics corresponding to BOMCOUNT,
BOMMASS, BOMBIRTH, BOMDEAD and BOMBEACH. OUTSIDE, cancellation and
missing-growth counters are also exposed in the event/counter record even if
an eight-character grid diagnostic is not registered.

Only ALIVE owner records contribute to count and mass. Event diagnostics count
accepted events once at commit, never proposals or retries.

## 18. MPI and reproducibility contract

Canonical records sorted by exact ID/event key must be bitwise identical for
serial, MPI2 and MPI4 under the same compiler and math mode:

- accepted T/N samples;
- S, status, parent and birth count;
- terminal decisions;
- Philox words, retry winner, angle and child position;
- birth IDs and bomNextId;
- live/dead/beached/outside/cancel budgets;
- post-event graph/raft values;
- trajectory/P4 sidecar/event records;
- continuous versus same-decomposition restart.

Collective reductions operate on integer counts/codes. Floating event state is
not summed in rank-dependent order. Event metadata is canonically sorted
before comparisons and ID allocation.

## 21. Change-control rule

Changing a formula, source policy, status/failure/phase/event number, RNG
constant/mapping, ordering key, retry rule, slot algorithm, schema field,
capacity semantic, tolerance or expected row count requires:

1. a named P4 decision amendment;
2. scientific or numerical justification;
3. affected requirements and tests;
4. regenerated checksummed references when applicable;
5. review before the production change.

Implementation convenience alone cannot override this freeze.
