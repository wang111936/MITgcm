## 2. Accepted v0.4 production facts

The Phase 4 design starts from these non-negotiable facts:

1. authoritative owner records occupy the compact prefix
   1:bomNPartTile on every local tile;
2. the accepted status values are 0 UNUSED, 1 ALIVE, 2 DEAD_BIO,
   3 BEACHED, 4 OUTSIDE, 5 INVALID and 6 WAITING;
3. failure values 0--25, RK stage values 0--8 and Phase 3 operation values
   0--9 are stable and cannot be renumbered;
4. Phase 3 owner migration packet schema 2 contains 10 integers and six
   reals, but no parent ID, amount or birth count;
5. owner state contains ID, status, position, release, age, physical
   diagnostics, spring fields and raft fields, but no biology or lineage;
6. ghost state is one-stage, read-only spring input and has no need for
   biology fields;
7. the schema-2 48-field core and required schema-3 eight-field P3 sidecar
   are released disk contracts;
8. BOM_MAIN commits a successful movement trial, then calls owner migration;
   there is no post-migration biology/land event transaction;
9. dry or out-of-domain RK trial positions currently report movement failure;
10. bomMaxEventBuffer is a value-one placeholder and is not a usable event
    store;
11. current owner and I/O loops assume the compact prefix throughout;
12. the v0.4 exact release path is protected by the 538-row gate.

## 3. Locked Julia Brooks behavior

The locked Brooks function evaluates:

    dS/dt = mu_max * temperature_factor * nutrient_factor - m
    nutrient_factor = 1 / (k_N / N + 1)

and the two-branch temperature factor recorded in the development manual.
At every accepted adaptive ODE solver step it first updates S by dS/dt times
the solver step, then tests strict lower and upper thresholds.

The source defaults differ between prose and constructor for S_min. The
constructor uses -1.0. Growth parameters are Julia defaults 0.1 d^-1,
0.05 d^-1 and 0.012 mmol N m^-3, while the project manual also records a
separate paper-scale example. Neither set is an implicit calibrated
production configuration.

The literal function reaches division by zero at exact temperature endpoints,
does not reject missing or negative nutrient input, and relies on host
floating-point behavior. The project manual already requires explicit
endpoint values, finite checks and non-negative nutrient clamping.

Finding P4-A: retain the named Brooks algebra and strict thresholds, but use a
stateless SI kernel with explicit Tmin/Tmax/Topt branches, finite validation,
N=max(N,0), and one fixed BOM substep update.

## 4. Locked Julia birth/death behavior

The Julia callback mutates S while discovering events. On an upper crossing it
resets the parent from a distribution before checking the hard clump limit.
A candidate removed by the hard cutoff can therefore retain a reset S even
though no child is created.

grow! increments n_clumps_tot and writes the next never-used vector index. It
does not reuse a dead slot. Once the ever-created count reaches the allocated
array length, later births fail even if nearly every earlier clump is dead.
The source also contains a string-location path that references an undefined
old-clump-count variable.

A child is placed one spring natural length from its parent at a global-RNG
uniform angle. There is no wet/land/outside retry, no parent lineage field, no
counter key and no MPI ordering contract. S for future slots is sampled in
advance when the model object is constructed.

Finding P4-B: Julia array indices and n_clumps_tot cannot define MITGCM-BOM
identity or capacity. Simultaneous live count, monotonically increasing exact
ID and reusable compact-tail slots are separate quantities.

Finding P4-C: birth is one collective event transaction. Parent S is reset
only with a successful child; a wet-placement cancellation restores the
parent's pre-biology S; capacity failure is fatal rather than a silent cutoff.

Finding P4-D: global RNG state is prohibited. A fixed counter algorithm and
the key seed/parent ID/parent birth count/event-time index/attempt must define
every angle independently of traversal and MPI layout.

## 5. Locked Julia land behavior

The Julia Land callback interpolates a binary field at current coordinates,
collects indices equal to 1.0, and calls the same kill! routine as biological
death. It does not:

- retain a distinct terminal reason;
- preserve a last accepted wet position;
- distinguish outside from land;
- retry a newborn;
- write an event record;
- make the state mutation transactional.

Finding P4-E: land, outside and biological death require distinct event types
and stable status codes even though terminal owner slots may be released after
their event records are buffered.

Finding P4-F: a stage-local boundary encounter cannot be treated as an
arbitrary interpolation error and cannot publish a dry coordinate. It becomes
a terminal candidate in scratch; the accepted event position is the last
substep-start wet position and the attempted position is retained only in the
event record.

## 6. Fixed-step and coupled-stage finding

Julia uses adaptive Tsit5 by default and callbacks at accepted solver steps.
MITGCM-BOM uses fixed RK2/RK4 substeps and, with springs, a synchronous
all-owner ensemble transaction. Removing one owner or changing array length
inside K1--K4 would invalidate the shared stage snapshot.

Finding P4-G: no owner count, slot, graph, event buffer or ID state changes
inside RK stages. Boundary classifications are scratch candidates. All
terminal and biology effects occur in the post-migration event transaction at
the complete substep time.

## 7. Rank-prefix ID discrepancy

The manual suggests rank-local birth counts followed by MPI exclusive prefix
sums, but separately requires identical birth IDs under 1/2/4-rank
decompositions. Rank order does not in general equal parent-ID order after
owner migration, so a rank prefix alone violates the latter requirement.

Finding P4-H: accepted birth candidates are globally ordered by exact parent
ID before assigning contiguous IDs from bomNextId. Phase 4 may allgather only
bounded event metadata, never the live particle set. A later distributed sort
may replace the implementation without changing the ordering semantics.

## 8. Compact storage and free-list finding

Changing v0.4 to a sparse array with internal holes would invalidate movement,
ghost, graph, migration, trajectory and pickup loops. A conventional arbitrary
slot free-list is therefore not a compatible first increment.

Finding P4-I: Phase 4 uses an explicit compact-tail free stack. Deletion swaps
the last valid owner into the removed slot, clears the old tail to UNUSED and
pushes that tail. Allocation pops exactly the next compact tail slot. Multiple
deletions are planned in descending current-slot order. Slot order is never an
identity; all deterministic operations use exact IDs.

## 9. Environment snapshot finding

Temperature and nutrient are sampled after movement at exact substep end
times. Ocean theta and PTRACERS are mutable model fields; external nutrient
files are time-varying. Reading them ad hoc during an event loop would make
results depend on call order and would break restart continuity.

Finding P4-J: P4.1 adds transactional accepted OLD/NEW temperature and nutrient
endpoints with validity and time metadata. Biology samples a shared-weight
wet C-point pair at tSub1. Pickup persists the accepted OLD bracket and its
metadata. Missing input follows an explicit STOP or NO_GROWTH policy.

## 10. Migration, schema and restart finding

Parent ID, S and birth count are authoritative fields and must follow an owner
across tiles/ranks. bomNextId and eventTimeIndex are global deterministic
state. The released schema-2 core and schema-3 P3 sidecar cannot be widened or
reinterpreted.

Finding P4-K: biology-enabled migration uses a new owner packet schema.
Container schema 4 adds a required P4 sidecar and retains existing core/P3
bytes. Pickup schema 4 additionally preserves global ID/event counters,
biology endpoints and unflushed event state or proves a pre-pickup flush.
Ghost schema 1 remains unchanged.

## 11. One-way coupling and phase boundary

The target is online particle biology driven by MITgcm fields. The first
version does not consume PTRACER nutrient, change theta, modify momentum, add
three-dimensional sinking, general-grid topology, OpenMP event allocation or
target-server scaling.

Finding P4-L: P4 is one-way, surface and regular-grid only. OpenMP/large-scale
event sorting belongs to Phase 5 and EXCH2/cubed-sphere/LLC belongs to Phase 6.
Those deferred tasks cannot be used to weaken serial/MPI1/2/4 correctness.
