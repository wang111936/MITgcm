# MITGCM-BOM P4.4 local closeout

Status: **LOCALLY COMPLETE; NOT PUSHED OR INTEGRATED**

P4.4 implements only the frozen schema-4 persistence, event publication,
diagnostic budget and same-decomposition restart increment. It does not claim
B19, P4-G99, the Phase 4 exit audit, v0.5 or target-server scaling.

## Accepted scope

- the released schema-2 trajectory (48 fields) and pickup (45 fields) cores
  remain unchanged; spring-enabled runs retain the released P3 sidecar;
- a required four-field P4 owner sidecar stores parent high/low words, amount
  S and birth count behind three fixed header records;
- schema-4 signatures and complete manifests freeze decomposition, source
  head, schedule, counters, biology sources and every member size/SHA-256;
- pure Fortran SHA-256 removes shell hashing from production I/O;
- per-rank schema-1 event shards use 32 exact hexadecimal words and a
  source/parameter/time/count/size/SHA manifest published last;
- forced, repeated and empty flushes are transactional; failure leaves the
  accepted buffer, shard, manifest and cumulative state unchanged;
- B18 validates exact live/free/ID/event budgets and registers BOMCOUNT,
  BOMMASS, BOMBIRTH, BOMDEAD and BOMBEACH diagnostics only after successful
  publication;
- schema-4 pickup preflights signatures, complete manifests and every event
  shard before publishing owners, then restores P4/P3 owner fields, counters,
  accepted T/N OLD/NEW brackets, event state and the deterministic compact
  tail free stack;
- changed decomposition remains rejected before state publication.

BOM remains an independent MITgcm package. No SKRIPS file or runtime path is
read or modified, and FLT is not a BOM dependency.

## Findings resolved during implementation

- schema-4 validation must precede every authoritative owner/counter/endpoint
  assignment, so all P4 members are decoded into scratch and committed once;
- event manifests are the publication point: a shard without its final
  manifest is not accepted state;
- portable exact INTEGER*8 reductions use high/low MPI_INTEGER words rather
  than the non-portable MPI_INTEGER8 datatype;
- BIRTH records identify the child as subject and retain the parent in its
  dedicated words; cancellation consumes neither child ID nor birth count;
- missing-growth counters are accumulated only after successful event commit;
- predecessor replay exposed two P4.2 direct-state fixtures that bypassed the
  released initialization path; the fixtures now establish the P4.4 next-ID
  watermark and reset prior event history at their explicit isolation boundary,
  while the production budget invariant remains strict;
- the cumulative P4.1 audit now has an explicit P4.4 scope: it distinguishes
  newly legal positive runtime capacity from the still-fatal absence of initial
  particle state without weakening any original P4.1 configuration rejection;
- predecessor performance replay now permits only the two high/low-word
  `MPI_Allgather` calls used by the exact P4 counter reduction and freezes their
  array shape and call count; spring/component gather remains forbidden;
- the independent P3-G99 aggregate audit enforces the same exact-count gather
  shape/count contract after all 538 predecessor rows are assembled;
- verification-only capacity overlays now carry every released P4.4 schema
  constant and differ from production `BOM_SIZE.h` only at their intended
  neighbor/event/ghost/exchange/tile limits;
- compiler `STOP` may return status zero, so negative gates require explicit
  fatal/preflight markers and absence of normal completion instead of relying
  on process status alone;
- Windows-to-WSL synchronization can add executable bits to Fortran sources;
  mode-only noise was removed before the closeout commit.
