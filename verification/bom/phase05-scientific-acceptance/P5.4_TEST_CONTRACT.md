# MITGCM-BOM P5.4 production-qualification test contract

Status: **FROZEN BEFORE P5.4 PRODUCTION EVALUATION**

This contract instantiates the P5-F01, P5-O01, P5-R01 and P5-L01 rows in
`SCIENTIFIC_ACCEPTANCE_PLAN.md`.  It does not replace or relax that plan.
All positive runs use the normal `pkg/bom` sources from one exact Git head;
no `bom_*.F` verification override may be present in a build mods directory.

## 1. Common rules

- Binary scientific inputs and BOM owner records are big-endian IEEE-754
  binary64 unless the standard MITgcm experiment already freezes another
  representation.
- Event and schema-4 files are decoded by Python standard-library readers
  which do not import, translate, execute or parse production Fortran.
- Exact fields (IDs, parents, status, event words, counters, checksums and
  pickup/restart bytes within one decomposition) are compared bitwise.
- Floating trajectory comparisons use
  `max(1e-6 m, 5e-11*reference_path_m)` unless a stricter exact comparison is
  stated below.
- A positive run must end normally and contain no `NaN`, `Inf`, stage failure,
  owner failure, budget failure or abnormal-end marker.
- A live owner must resolve uniquely to a supported wet cell.  A terminal
  owner may appear only in the event stream and retains its last accepted wet
  position plus the rejected attempted position and RK stage.
- A fresh biological owner starts with `S=bomS0`, `parent_id=0` and
  `birth_count=0`.  This is the only admissible fresh-start interpretation;
  restart values come exclusively from the validated schema-4 sidecar.

## 2. P5-F01 manufactured production system

The Cartesian grid is 8 x 6 x 2, with 1000 m horizontal cells and four
logical tiles.  Serial and MPI-4 layouts represent the same global grid.
Ocean momentum and tracers are frozen, so only BOM advances.

### F-SPRING

- IDs 101, 202 and 303 start alive at `(2500,2500)`, `(2700,2500)` and
  `(2500,2700)` m in a fully wet domain.
- `bomSpringLaw=EBOMB`, `bomSpringL=100 m`, `bomSpringA=1e-3 s^-2`,
  `bomSpringDelta=25 m`, cutoff 350 m, minimum distance `1e-6 m`,
  `bomTauDays=1/86400 day`, RK4 step 20 s and four advances.
- Current, wind and Stokes drift are exactly zero.
- The independent oracle constructs the initial ID-sorted graph, evaluates
  each pair from the frozen eBOMB law, checks equal-and-opposite pair
  contributions and center-of-mass conservation, and integrates the complete
  three-owner ensemble with independent fixed-step RK4.
- Initial graph edges are exactly `(101,202)`, `(101,303)`, `(202,303)` and
  the component ID is 101 with size 3.

### F-EVENT

Three one-step subcases use one fresh owner, constant temperature/nutrient,
zero flow and no spring graph:

1. `birth`: ID 1001, fully wet interior, `T=20`, `N=1`, `mu=1000/day`,
   mortality 0, `kN=1`, `S0=1`, `Smin=0.5`, `Smax=1.5`, step 100 s and
   placement radius 100 m.  Exactly one successful BIRTH is required.
2. `cancel`: the same biological law and parent, but placement radius
   10000 m, larger than the domain diagonal.  Exactly one BIRTH_CANCEL is
   required after exactly `bomBirthMaxTry=4` retries; no child ID is consumed.
3. `death`: ID 1001, `T=20`, `N=1`, `mu=0`, mortality 1000/day,
   `S0=1`, `Smin=0.5`, `Smax=1.5`, step 100 s.  Exactly one DEAD_BIO record
   is required and no live owner remains.

For every record the independent oracle fixes the event type, time index,
time, iteration/substep, subject/parent/child IDs, retry, source/destination,
status transition and `(S_before,S_trial,S_after)` values.  Successful child
placement is reproduced from the independent Philox implementation and must
match the accepted retry, coordinates and exact next ID.  The cancel case
must leave the parent amount at `S_before` and preserve `next_id`.

### F-COAST

- ID 2001 starts immediately west of one dry interior cell and ID 2002 starts
  immediately west of the nonperiodic eastern boundary.
- Constant eastward ocean flow and one 100 s nominal RK4 advance cause the
  first owner to become BEACHED and the second OUTSIDE at their analytically
  frozen first invalid RK stages.
- The event stream must distinguish the types and contain exact last-wet and
  attempted coordinates.  No terminal owner may remain in owner output.

### F-COMBINED

- One 100 s short run enables EBOMB, Brooks biology, land handling, births
  and deaths, raft diagnostics, schema 4, event shards, a BOM pickup and a
  trajectory frame.
- Spatially frozen temperature creates one successful birth and one
  biological death from fresh owners.  The surviving parent and child form
  the expected post-transaction component.
- The independent artifact reader verifies core/P3/P4 owner alignment,
  released core schemas, frame sizes and SHA-256 values, parent/amount/birth
  sidecars, event manifests and shards, graph/component reconstruction,
  live/free/next-ID/mass/event budgets and pickup consistency.

## 3. P5-O01 baroclinic-gyre smoke

- `verification/tutorial_baroclinic_gyre` is copied byte-for-byte to an
  external run root; no standard-case file is modified.
- One production executable and one MPI layout run the existing 10 x 1200 s
  spherical 62 x 62 x 15 experiment with BOM off and with BOM on.
- Ocean pickup/state and a frozen inventory of selected diagnostics are
  byte-identical between off/on runs.
- BOM executes ten nonzero advances, keeps finite nonzero paths and valid wet
  owners, and its archived surface endpoints plus initial particles reproduce
  the production PAPER2024 paths under an independent sparse-step replay.
- Serial/MPI-4 IDs, states and decisions are exact; coordinates and paths use
  the common floating bound.

## 4. P5-R01 restart/decomposition matrix

- The matrix contains Case J and F-COMBINED in serial, MPI-2 and MPI-4.
- Continuous runs are compared with runs split at a nonfinal BOM pickup;
  F-COMBINED is additionally split across an event boundary before the event
  buffer would otherwise be flushed by a trajectory write.
- Within a decomposition, restart owner state and every subsequent output
  member are byte-identical.  Across decompositions, canonical IDs, parents,
  statuses, birth counters, Philox decisions and events are exact; floating
  coordinates use the common bound.
- There are no missing or duplicate IDs, time indices, fields or events.
- A deliberately changed decomposition signature is rejected before any
  owner or sidecar publication.

## 5. P5-L01 controlled 30-day run

- PAPER2024 uses the controlled periodic P5 fields, hourly trajectory output,
  daily BOM pickups, a fixed MPI layout and exactly 30 model days.
- Continuous and day-15 restart runs must have exact IDs, state/event/mass
  budgets and byte-identical subsequent pickup/trajectory members.
- Every saved value is finite.  Live slots, free-stack usage, event-buffer
  occupancy and file-manifest counts show no monotonic leak.
- Wall time, peak RSS, output bytes and available per-step BOM timers are
  recorded.  They are diagnostic only and carry no speed threshold.
