# MITGCM-BOM P3.0 springs and distributed-neighbor interface freeze

Status: **FROZEN FOR P3.1--P3.5 IMPLEMENTATION**

Baseline: `MITGCM-BOM-v0.3` / commit
`332a406e958e5005f60267c187fada1f74319fc3`

Target: `MITGCM-BOM-v0.4`

## 1. Scope and compatibility boundary

Phase 3 adds only:

- a locked small-system K-nearest reference oracle;
- canonical Cartesian/spherical pair geometry;
- Hooke and eBOMB spring velocity;
- an exact-radius cutoff graph generated by a production cell-linked list;
- per-stage read-only ghost exchange;
- synchronous ensemble RK2/RK4 transactions;
- deterministic connected-component/raft diagnostics;
- container schema 3 and local algorithmic/performance evidence.

Phase 3 does not add growth, birth/death, land/beaching transitions, stochastic
physics, changed-decomposition restart, EXCH2/general grids, OpenMP production
support, two-way ocean feedback or target-server scaling.

`bomSpringLaw='NONE'` remains the default. That path must call the accepted
v0.3 per-particle integrators without new arithmetic, collectives, graph work or
schema changes. `LEEW` may not enable springs in Phase 3.

## 2. Authority and units

Authority order for Phase 3 is:

1. equations and staged decisions in the project development manual;
2. this interface freeze and its source audit;
3. locked Julia commit `156557359185e4413ce82829f3ed26a4eb8c6283`
   for named compatibility fixtures;
4. implementation convenience.

All production spring quantities use SI:

| Quantity | Symbol | Unit |
|---|---|---|
| natural length | `L` | m |
| pair distance/cutoff/smoothing | `d`, `rCut`, `Delta` | m |
| Hooke/eBOMB stiffness | `k0`, `A` | s^-2 |
| inertial response time | `tau` | s |
| spring drift contribution | `vSpring` | m s^-1 |

The Julia standard comparison converts its kilometre distance unit to metres;
literal `BOMBSpring(...,0.2)` smoothing therefore means `Delta=200 m`.

## 3. Runtime parameter contract

The Phase 3 parameters are appended to `BOM_PARM01`/`BOM_PARM02`; no existing
name or default changes.

| Parameter | Type/unit | Frozen meaning |
|---|---|---|
| `bomSpringLaw` | character | `NONE`, `HOOKE`, or `EBOMB` |
| `bomNeighborPolicy` | character | `NONE` or production `CUTOFF` |
| `bomSpringL` | m | one global natural length used by every Phase 3 edge |
| `bomHookeK` | s^-2 | constant Hooke stiffness |
| `bomSpringA` | s^-2 | eBOMB stiffness amplitude |
| `bomSpringDelta` | m | eBOMB logistic smoothing length |
| `bomNeighborCutoff` | m | exact accepted-edge radius |
| `bomPairDistanceMin` | m | unresolved-pair rejection threshold |
| `bomSpringCFL` | dimensionless | upper bound on `dt*tau*kMax*nNbr` |
| `bomRaftDiagnostics` | logical | compute FINAL connected components and sidecar fields |

Frozen defaults are `NONE`, `NONE`, numeric zero, `bomSpringCFL=0.5`, and
`bomRaftDiagnostics=.FALSE.`. Numeric spring values are ignored only when
`bomSpringLaw='NONE'`.

For an enabled spring law:

- `bomMode` must be `BOM`;
- `bomNeighborPolicy` must be `CUTOFF`;
- `bomSpringL`, `bomNeighborCutoff`, `bomPairDistanceMin`, `bomSpringCFL` and
  the selected stiffness must be finite and positive;
- `bomNeighborCutoff` must exceed `bomPairDistanceMin`;
- `HOOKE` requires positive `bomHookeK`;
- `EBOMB` requires positive `bomSpringA` and `bomSpringDelta`;
- the supported periodic domain requires a unique shortest image at the
  cutoff: no accepted pair may reach half the physical X period;
- `bomRaftDiagnostics` requires springs enabled in Phase 3.

The common eBOMB choice
`rCut=2*L+nDeltaCut*Delta` remains a documented configuration formula, with
`nDeltaCut=8` recommended. Production uses the explicit stored
`bomNeighborCutoff`; it does not silently recompute it.

## 6. Canonical pair geometry

`BOM_PAIR_GEOMETRY` is a stateless helper. Inputs are the two exact positive
IDs and trial positions. Outputs are canonical east/north displacement from
low ID to high ID, distance and validity.

Rules:

1. reject equal IDs, non-finite coordinates and unsupported grid modes;
2. orient the pair as `(idLo,idHi)` independent of caller/owner;
3. normalize periodic-X displacement to `[-period/2,period/2)`; an exact
   half-period pair is outside the supported cutoff contract and rejected;
4. Cartesian displacement is the canonical native-metre difference;
5. spherical-polar displacement uses shortest longitude, latitude difference,
   `rSphere`, and the pair midpoint latitude for one symmetric local
   east/north metric;
6. retain the Phase 2 radius, finite-cosine and near-pole rejection rules;
7. compute distance with an overflow-safe norm;
8. reject `d<=bomPairDistanceMin`; do not skip or invent a direction;
9. the caller applies `+/-` according to whether its ID is low/high.

Both owners of a distributed edge must obtain bitwise-identical canonical
displacement, distance and stiffness before applying opposite signs.

## 7. K-nearest reference and natural length

The KNN implementation is kept under `verification/bom/phase03-springs-neighbors`
and is never compiled into `pkg/bom`.

For every live particle `i` in a fixture:

1. form canonical distances to every other live particle;
2. order candidates by `(distance,globalId)`;
3. select `min(K,N-1)` non-self candidates;
4. require `N>=2` and `K>=1`;
5. define `mean_i` as the arithmetic mean of selected distances;
6. define `LOracle` as the deterministic median of `mean_i` values, using the
   average of the two middle values for even `N`.

Production reads an explicit `bomSpringL`; it never performs runtime global
KNN. P3.1 fixtures store both the frozen oracle result and the result from the
literal locked-Julia `DeltaL(ics;k)` convention so its self-count discrepancy
is visible rather than silently normalized.

## 8. Exact cutoff graph

The mathematical graph, independent of candidate generation, is:

```text
edge(i,j) iff i!=j, both are ALIVE, geometry is valid, and d(i,j)<=rCut.
```

- Equality at `rCut` is included.
- Each owner neighbor list excludes self and duplicate IDs.
- IDs are strictly increasing before spring accumulation.
- The directed owner lists must represent one symmetric undirected graph.
- WAITING, UNUSED and later Phase 4 terminal states do not enter the graph.
- Graph content is stage-local scratch until the whole stage validates.

The accepted edge set from the production path must equal the verification
oracle edge set exactly for every small fixture.

## 9. Production cell-linked list

`BOM_INIT_CELL_GEOMETRY` freezes a regular-grid-compatible half-open cell plan.
`BOM_BUILD_CELL_LIST` rebuilds head/next arrays for owner and current-stage
ghost candidates. `BOM_BUILD_NEIGHBORS` enumerates only the conservative cell
stencil and applies the exact graph filter.

Required properties:

- a point on a cell face is assigned by mathematical floor to one cell;
- periodic-X cell indices wrap, regional boundaries do not clamp;
- spherical rows carry a conservative X reach derived from their minimum
  supported physical zonal metric; exact pair geometry is still authoritative;
- every pair within the cutoff is guaranteed to occur in the enumerated
  candidate cells;
- owner and ghost copies of the same ID are deduplicated before graph output;
- head, next, candidate and neighbor storage are statically bounded;
- Phase 3 rebuilds at every K stage and FINAL; no Verlet/skin reuse;
- no global particle gather, allgather, root list or all-particle nested loop is
  present in `pkg/bom`.

Runtime work counters include owner records, ghost records, non-empty cells,
candidate comparisons, directed accepted neighbors, undirected edges and
maximum neighbors per owner.

## 10. Ghost exchange contract

`BOM_GHOST_EXCHANGE` is independent of owner migration. A version-1 ghost
packet contains:

| Field class | Fields |
|---|---|
| integer | schema, stage, epoch, ID high, ID low, status, source rank, source tile-i, source tile-j |
| real | trial X, trial Y |

The packet carries no age, release state, environment diagnostic, output state
or pickup state. Global spring parameters are not duplicated per ghost.

The exchange transaction is:

1. clear readiness and count every required destination from trial positions;
2. validate source IDs/status/coordinates and all send/per-tile capacities;
3. exchange counts, validate receive capacities, then exchange packets;
4. validate schema/stage/epoch/source, exact IDs, finite coordinates,
   unexpected duplicates and spatial relevance;
5. sort each tile's ghosts by full positive ID;
6. publish count and readiness once after a global zero-error reduction.

All ranks enter the same collectives even with zero local owners. A ghost is
read-only and valid for exactly one `(substep,stage,epoch)`. It never contributes
to owner counts, output, pickup, migration or component size by itself.

The tile adjacency plan is precomputed from supported regular-grid bounds and
the cutoff. Packets are sent only to tiles whose cutoff-inflated bounds can
intersect the stage point. Unsupported topology or non-unique periodic image is
a configuration failure.

## 11. Stateless spring law

`BOM_SPRING_PAIR` receives canonical displacement/distance and returns the
low-ID particle's east/north spring velocity candidate.

For Hooke:

```text
k(d) = bomHookeK
```

For eBOMB:

```text
z = (d - 2*L)/Delta
k(d) = A/(exp(z)+1)
```

The logistic is evaluated without positive-exponent overflow:

- `z>=0`: `k=A*exp(-z)/(1+exp(-z))`;
- `z<0`: `k=A/(1+exp(z))`.

The canonical low-ID velocity is:

```text
vSpringLo = tau*k(d)*(L/d - 1)*(xLo - xHi)_EN.
```

The high-ID owner applies the exact negative candidate. Every division,
multiplication, addition and accumulated component is finite/overflow checked.
The routine is stateless and never changes owners, ghosts, graph or particles.

Each owner accumulates its neighbors in strictly increasing global-ID order.
The same local-local edge is evaluated separately for both endpoints using the
canonical pair helper; no remote reverse-force message or atomic write exists.

## 12. Phase 2 RHS composition

The accepted Phase 2 `BOM_RHS_SLOW_MANIFOLD` remains the base-flow evaluator.
For an enabled spring stage:

1. evaluate its unmodified base RHS and 27 diagnostics;
2. evaluate ID-sorted spring east/north velocity from the accepted stage graph;
3. set diagnostic 26/27 (`final drift`) to base drift plus spring velocity;
4. preserve diagnostics 1--25 exactly;
5. convert only the spring east/north contribution with the same Cartesian or
   spherical native-rate rule and add it to the base native rate;
6. recompute the advective CFL from the combined final drift;
7. publish separate spring east/north diagnostics in P3 state.

`bomSpringLaw='NONE'` bypasses all six additions and calls the exact v0.3 path.

## 13. Spring stability

At each owner and stage:

```text
springNumber = dtGuard*tau*kMax*nNeighbor
```

where `kMax=bomHookeK` for Hooke and `kMax=bomSpringA` for eBOMB. A positive
`dtGuard` requires `springNumber<=bomSpringCFL`. The existing advective CFL is
also evaluated on the combined drift and must satisfy `bomAdvCFL`.

These are necessary guards, not accuracy proofs. B07 convergence/refinement
tests decide acceptable production time steps. FINAL diagnostic refresh uses
`dtGuard=0` but still checks all pair and accumulated values for finiteness.

## 14. Ensemble RK transaction

Spring-enabled integration uses `BOM_RK2_SPRING_ENSEMBLE` or
`BOM_RK4_SPRING_ENSEMBLE`; the per-particle v0.3 routines are not called as
the outer scheduler.

At the start of a nominal substep, snapshot all authoritative owner positions,
IDs, status and diagnostics into bounded scratch. For each required K stage:

1. build every owner trial position from the same X0 and prior K arrays;
2. validate position and existing-owner overlap rules globally;
3. exchange stage ghosts transactionally;
4. build cell lists and the exact cutoff graph;
5. evaluate ID-sorted spring velocity for every owner;
6. evaluate the Phase 2 base RHS at the exact stage position/time;
7. combine rates and run finite, advective and spring guards;
8. reduce errors globally before another stage begins.

FINAL repeats graph/spring/base-RHS evaluation at the accepted trial position,
then computes component labels when enabled. No authoritative particle field,
P3 diagnostic, graph-ready flag or schedule changes until every rank validates
the entire substep.

On success, positions, Phase 2 diagnostics, spring diagnostics and component
labels are committed together. Existing owner migration then moves the complete
accepted record. On any pre-commit failure every authoritative byte and output
schedule remains unchanged.

All ranks execute the same collective sequence. A zero-owner rank participates
with zero counts; it does not return early across a collective boundary.

## 15. Owner and migration extension

Owner identity stays fixed during K stages. Trial positions may use the
accepted Phase 2 field overlap but cannot silently change owner. After a full
substep commit, the existing owner transaction runs once and carries the Phase
3 accepted fields:

- spring east/north velocity;
- neighbor count;
- raft ID high/low words;
- raft/component size.

Migration packets increment their schema/version explicitly. Counts and packet
capacity are preflighted before authoritative owner replacement. A ghost packet
can never be consumed as an owner migration packet.

## 16. Connected components and raft diagnostics

The authoritative graph for components is the successful FINAL cutoff graph.
Each live owner starts with label `globalId`. Deterministic min-label
propagation sends current labels across existing edges/ghost routes and updates
an owner to the smallest observed label. Iteration continues until a global
no-change reduction.

- `bomRaftId` is the converged minimum positive ID;
- a singleton has its own ID;
- `bomRaftSize` is the exact global count for that label;
- labels/counts are owner fields and move with owner migration;
- convergence must occur within `NAlive` iterations; otherwise fail 24;
- message/slot/rank order may not affect the label;
- graph edges are not persistent state and are rebuilt next stage.

Phase 3 has no explicit permanent bond state. The raft is the connected
component of the instantaneous cutoff graph. Adding hysteresis or edge state
would require a new schema and design decision.

## 17. Diagnostics and counters

Per accepted owner:

- `bomSpringEast`, `bomSpringNorth` in m/s;
- `bomNeighborCount`;
- exact `bomRaftId`;
- `bomRaftSize`;
- existing `bomRhsDiag(26:27)` as combined final drift.

Per substep/rank and globally reduced at diagnostics points:

- owner and ghost counts;
- non-empty cells and rebuild count;
- candidate comparisons;
- directed neighbors and undirected edges;
- maximum neighbors, ghosts and component size;
- ghost records/bytes sent and received;
- component iterations.

Integer counters use overflow-checked 64-bit storage. They are diagnostics, not
inputs to floating-point accumulation.

## 18. Container schema 3

Container schema 3 preserves the schema-2 48-field trajectory core, 45-field
pickup core, endpoint sidecars and diagnostics 1--27. It adds a required P3
sidecar keyed by the core record's exact ID.

P3 sidecar particle fields are:

1. particle ID high word;
2. particle ID low word;
3. raft ID high word;
4. raft ID low word;
5. neighbor count;
6. raft size;
7. spring east velocity;
8. spring north velocity.

Header/signature metadata includes container schema `3`, sidecar schema `1`,
field count `8`, spring/neighbor codes, all Phase 3 real parameters, compile
capacities, packet versions, decomposition signature and the unchanged Phase 2
fingerprint. Exact IDs are never converted to a single float64.

The schema-3 pickup read is one transaction:

1. validate Phase 2 signature/core/environment exactly as schema 2;
2. read core and P3 sidecar into scratch;
3. require one-to-one exact ID/order correspondence;
4. validate finite values, integer bounds and component invariants;
5. rebuild scratch FINAL graph, spring diagnostics and components;
6. require exact neighbor/raft fields and bitwise spring diagnostics;
7. commit Phase 2 and Phase 3 state once after all ranks pass.

Missing, truncated, extra, reordered or corrupted sidecar data fails with code
25 before publication. Same-decomposition restart remains mandatory.

Trajectory core/sidecar frames share exact time, iteration, tile record count
and schedule. A partial frame is invalid evidence.

## 19. Verification oracle and production separation

The reference oracle may use all-pairs or a Julia KD/Ball tree only when:

- it is located under `verification/bom/phase03-springs-neighbors`;
- particle count does not exceed its frozen fixture limit;
- it writes canonical ID-sorted graph and pair-contribution records;
- it is never linked into a production MITgcm executable.

Production `pkg/bom` may not call `MPI_Gather`, `MPI_Gatherv`,
`MPI_Allgather`, or `MPI_Allgatherv` for neighbor construction. Existing
debug/global-ID checks outside the Phase 3 neighbor path do not authorize such
calls inside it.

## 20. Performance acceptance boundary

Phase 3 local performance evidence combines:

1. a source/linked-symbol audit proving no production all-pairs/gather path;
2. exact runtime work counters;
3. fixed-density Cartesian and spherical fixtures at increasing N;
4. serial/MPI2/MPI4 timings recorded with build and environment metadata;
5. capacity/fail-closed tests for deliberately dense cells.

For the frozen fixed-density fixtures, candidate comparisons per owner and
ghosts per boundary owner must remain below explicit fixture bounds and must
not grow in proportion to global N. Timing is reported but is not the sole
pass criterion on shared WSL hardware.

The Phase 5 goals of 100,000 clumps, 256 ranks and less than 20% ocean-model
overhead are not claimed by Phase 3.

## 22. Design decisions

| ID | Frozen decision |
